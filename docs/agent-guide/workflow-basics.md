# Workflow basics
Build from a template, inspect the graph, agree costs and review the results.

1. Read this topic with `get_guide` before building or starting. Use `list_templates` to find a template and its input IDs, then `create_from_template`. Missing required inputs leave a draft. Use `upload_asset` for files (songs, videos, images, documents) and pass its asset_id as an input. If the file is on the internet (a Suno or CDN link, a Dropbox or Google Drive share link), give `url` and the app downloads it; this also works when your own machine cannot reach the app. Small files can go as data_base64, large local files through the upload link (PUT). To put a file into an input node of a workflow (for example the audio input that holds the song), use `edit_workflow` set_params with the asset_id: {"asset": "<asset_id>"}.
2. Read `get_workflow` with include_graph: true, then `list_node_types` with the relevant types. Use `edit_workflow` to add nodes, connect ports or set parameters; it does not start work. `duplicate_workflow` accepts workflow_id and an optional name for a copy.
3. Call `estimate_run` before every run with the intended inputs and scope. Explain paid steps and the estimate to the person; obtain their approval of the cost ceiling before starting paid work. Call `run_workflow` with workflow_id and max_usd, then follow its run_id with `get_run`. Give the person the returned workflow url.
4. For partial runs, estimate and run the same scope: mode: "node" or "selection" with node_ids; mode: "items" with node_id and items (zero-based indexes). The default mode is "all". Required upstream nodes are included. Items mode needs an existing selected list result with item keys and valid indexes; it remakes the selected items, reusing other available items.
5. Matching cached steps do not run again. The cache key includes node type/version, relevant parameters, input fingerprints and any state stamp. App source code is not hashed: a code edit alone can leave the old result reusable. To recompute an affected node, estimate and run mode: "node", node_ids: [the node ID], force: true. Force bypasses that target's cached result; it can cost again.
6. A run pauses with status awaiting_approval when its next paid step would exceed the approved max_usd. `get_run` then shows approval (the step, estimated_usd, required_usd, max_usd). Tell the person the amount and ask. After their yes use `resume_run` with run_id and the agreed higher max_usd; otherwise use `cancel_run`. `resume_run` works only for runs started with the same key and within the key's limits.
7. Inspect `get_workflow_results` with workflow_id (optional node_id, text_chars, history_limit). Check text and file links, retain asset_id for reuse, and give the person the links. History entries include entry_id. `get_workflow_costs` reports costs already incurred. Only after the person's explicit yes may `delete_result_entry` remove a history entry using workflow_id, node_id, entry_id and confirm: true.

No MCP tool deletes a whole workflow or influencer. Suno tools are read-only: `suno_status`, `suno_library`, `suno_audio`; they do not generate songs.
