# Node View — Implementation Notes

Status: v1 as built, plus phase 2c (Higgsfield lip sync, voice change, motion transfer and speech; 2026-09-29) the fal.ai / MiniMax H3 Max nodes (2026-09-29, §2.7) the Prompt node with its quick pick (2026-09-29, §2.8) the port hover help with visible multi-inputs (2026-09-30, §2.9) and the clarity of the Motion graphics node (2026-09-30, §2.10). Companion to [SPEC.md](SPEC.md). The SPEC is the design that was implemented; this file records the architecture as it ended up, every relevant deviation from the SPEC, a recipe for adding node types, the tests, the decisions taken and the backlog. **Where the SPEC and the code disagree, the code wins.**

## 1. Architecture in short

```
Browser   public/nodes/*.js   (window.OCDNodes, classic scripts, no build)
  │  REST + SSE
server.js ─ registerNodeRoutes(app, deps)                         lib/nodes/routes.js
  │           └─ createEngine({ store, getConfig })                lib/nodes/engine.js
  ├─ workflows-store   data/workflows/<wfId>/{workflow.json, results.json, runs/<runId>.json}
  ├─ registry          nodes-basic · nodes-generate · nodes-fal · nodes-edit   (declarative definitions + executors)
  ├─ events            per-workflow bus → SSE
  └─ reused unchanged  tools.executeTool · store (sessions, ledger) · poller · ffmpeg · OpenRouter / ChatGPT
                       Higgsfield · fal.ai · ElevenLabs · render nodes · cost journal
```

- **One hidden backing session per workflow** (`kind: 'workflow'`, title `Workflow: <name>`, same `folder` as the workflow). Every input and output is a ledger asset of that session; chat assets are copied in. `store.listSessions` skips such sessions unless `includeHidden: true`; the poller passes it, so async jobs complete exactly as in the chat. Deleting a workflow deletes its folder and the backing session including all assets; cost journal lines remain.
- **Executors are thin adapters** over existing code (`tools.executeTool`, `lib/nodes/llm.js`, `lib/ffmpeg.js`, resvg, the Higgsfield catalogue). Provider costs are journaled by those tools and show up in the normal cost summary under the backing session.
- **Two writers, two files.** The client owns `workflow.json` (autosave, optimistic `rev`); the engine owns `results.json` (history, selected variant) and `runs/`. Variant selection goes through `PATCH …/results/:nodeId`. Locks: `wf:<id>` for `workflow.json`, `wf-results:<id>` for `results.json` (`store.withLock` is not re-entrant, never nest them).
- **Registry-driven UI.** Cards, palette, inspector and pre-run validation are generated from `GET /api/nodes/registry`. A new node type needs no client code, only i18n rows.
- **Values.** `{type:'text'|'number', value}`, media `{type:'image'|'video'|'audio', sessionId, assetId, file, url, duration?}`, lists `{type:'list', of, items}`.
- **Language.** Errors of the node modules are English; errors that come from `lib/tools.js` stay German, as in the chat.
- **72 node types:** 14 basic, 23 generative, 9 fal.ai, 26 editing (`registry.list()`).

## 2. As built vs. SPEC

### 2.1 Registry and node definitions

- **Hidden result port on `output.result`.** SPEC: no output. Built: one hidden output `result:any` (`hidden: true`) that stores the received list, because ZIP download, send-to-chat, thumbnails and Design App outputs read it from `results.json`. Validation rejects edges from hidden ports (`bad_port`); the client never draws them.
- **`portVariants`** (new optional field): `{ param, values: { <value>: { inputs?, outputs? } } }` switches ports by a param value. Used by `input.media_list` (`kind` → `image[]` / `video[]` / `audio[]`) and `hf.remove_background` (`kind` → image / video), because port types have no union. Resolve the ports of a concrete node with `registry.portsFor(def, params)` (the client mirrors it in `graph.portsFor`); `def.inputs` / `def.outputs` are only the defaults.
- **`createRegistry()` and `registerAll(registry)`.** `createRegistry()` builds isolated registries (tests); `registry.js` also exports the default instance and its bound methods. Node modules export `registerAll(registry)`; the default registry loads all three at the bottom of `registry.js`.
- **Multi-edge ports (`multiple: true`).** The executor receives one list value `{type:'list', of, items}` with all edges flattened in `graph.edges` order (a `T[]` edge contributes its items). Used by `text.join`, `util.router`, `output.result`, `image.edit.images`, `video.concat.clips` and others. A port-level `max` is enforced by the node's `validate` / `execute`, not by the engine.
- **Definition and param extras.** Definition: `async: true` (30-min instead of 12-min timeout), `timeoutMs`, `experimental`, `description`. Param: `optional` (blank number → `null`), `accept`, `showIf: { param, equals }`, `dynamic: 'higgsfield-model'`, `max` on `assets`. `validate(params, ports)` returns strings (errors) or `{ level: 'warning' | 'error', message }`. `available()` returns `true` or a reason string.
- **Unavailable and experimental nodes stay visible.** SPEC §5.8: the Higgsfield edit nodes appear only when Higgsfield is connected and `PUBLIC_BASE_URL` is set. Built: they are always registered; without Higgsfield (and, for the ffmpeg-probing ones, ffmpeg) `available` is a reason string and the palette lists them dimmed with an "unavailable" badge; all `hf.*` carry an "experimental" badge. Since phase 2c `PUBLIC_BASE_URL` is no longer a precondition: without it the sources are uploaded with `media_upload` (§2.6).
- **Higgsfield generation nodes.** Category `higgsfield` (not `image` / `video`) for `image.higgsfield`, `video.higgsfield` and `hf.*`. The SPEC left the storage of dynamic params open: `aspect_ratio`, `resolution` (text) and, for video, `duration` (integer, optional) are real params; all other model parameters live as a JSON object string in param `extra_params` (kind `code`, default `"{}"`). `GET /api/nodes/higgsfield-models/:id` returns a `target` per param (`aspect_ratio`, `resolution`, `duration` or `extra_params`) telling the client where to write the value. If `extra_params` has keys but the model cannot be checked (`models_explore get`), the run aborts before anything is reserved or paid; unknown, reserved, already-set or mistyped keys are dropped and reported in `node_log`.
- **LLM nodes.** `model` defaults to `''`, meaning `config.defaultBrain` at run time. All LLM nodes are `paid: true` (USD; ChatGPT subscription = 0) so plan totals and the confirmation count them. OpenRouter requests send `usage: { include: true }`. `chatgpt/*` models use `chatgpt.streamResponses` (JSON via the system prompt, no temperature, journal cost 0 / `billing: 'Abo'`).
- **`llm.motion_html` / `video.motion_graphics`.** The HTML uses `{{asset:N}}` placeholders (1-based, edge order) that `video.motion_graphics` replaces with `<assetId><ext>`. Both `assets` ports are type `any` (no union types); the run checks that only image / video / audio arrive.
- **`count` on generative nodes.** A failing variant does not discard paid ones: the node fails only if every variant fails, otherwise the error is logged (`N of M variants failed: …`). Inside a list map `count` is forced to 1.
- **Editing nodes: parameters beyond the SPEC table.** `image.resize.transparent`, `image.pad.transparent`, `image.pad.mode` (`aspect` | `size`); `unit` (`px` | `percent`) and `anchor` (`top-left` | `center`) on `image.composite` and `video.overlay_image`; `audio.mix.volumes` is a comma-separated text param (`amix` keeps its default normalisation, older ffmpeg builds lack `normalize=0`); `video.trim` `end = 0` means "to the end"; `video.extract_frame` `last` = duration − 2 frames; `image.to_video` zooms a fixed 20 %, always writes even sizes, max 600 s. A mask in `image.composite` replaces the layer alpha (white = visible); blend modes other than `normal` are computed on the layer footprint only. Outputs: PNG, MP4 (H.264 + AAC), M4A. Local nodes write no cost-journal lines. `media.info` is in category `utility`.
- **List limits.** The engine maps at most 50 items (`limits.maxListItems`). A longer list on a scalar port fails at run time ("List has N items; the limit is 50"), although `input.text_list.max` and `text.split.max` accept up to 500. `input.media_list` caps at 50.

### 2.2 Engine

- **Cache key.** `sha256(canonicalJSON({ t: type, v: def.version, p: params, i: fingerprints }))`. The SPEC used the node's `typeVersion`; built uses the registry's `def.version`, so changing an executor invalidates cached results (**bump `version`** when the output for the same inputs changes). Params are normalised first (defaults, coercion, min / max clamp); `label` and `title` are excluded. The `typeVersion` stored in nodes is kept but not used for caching.
- **Cache hits prefer the selected entry.** Forced re-runs create several entries with the same key. `findCacheHit` returns the entry the user selected before a newer one, so runs and plans never swap a chosen older version or mark its successors stale.
- **Lists and partial results.** Implicit map as in the SPEC (zip by index, max 50, `count` = 1, `node_status.progress = {done, total}`). If a map fails or is cancelled, the finished items are kept: their cost is booked into the run and they are stored in `results.nodes[id].partial = { cacheKey, runId, createdAt, items: { "<index>": { variant } }, errors: [{ index, message }] }`. The node still ends as `error` (downstream `skipped`). The next run with the same cache key skips finished items (only missing ones are executed and paid); a forced run ignores `partial`; `partial` is deleted after a successful run. `plan.nodes[id].executions` counts only the items still to run, `reusedItems` says how many are reused. Partial items are not history entries and not visible in the UI (their assets stay in the backing session).
- **Scheduling details.** FIFO semaphore; a node's pool slot is released while `ctx.waitForJob` waits and re-acquired afterwards; `ctx.withLocalSlot(fn)` takes one of `limits.localJobs = 2` server-wide slots (all ffmpeg work). Timeouts 12 min (sync) / 30 min (`async: true`) → error code `NODE_TIMEOUT`. Env: `NODES_MAX_PARALLEL` (3), `NODES_MAX_ACTIVE_RUNS` (4). Kept: 50 run records, 30 history entries per node.
- **Cost preview.** No price table. `estimate` = `def.cost.estimate(params, …)` if defined; otherwise, for `usd` nodes, the newest actual cost of the same node type in this workflow (scaled by `count`); otherwise `null` ("unknown"). Higgsfield nodes estimate credits from the catalogue. Totals: `{ paidNodes, usd, credits, unknownNodes }`. The engine never writes cost lines: executors report `cost` and the underlying tools journal it; `run_cost` events carry the running totals.
- **Executor context** in addition to SPEC §9.5: `itemIndex` (inside a map), `withLocalSlot(fn)`, and `toolCtx.nodeView = true`. Executors receive normalised params and inputs already adapted to their port types (numbers stringified for text ports, lists wrapped or mapped); outputs are checked against port types and `isValue`.
- **Restart.** `markInterruptedRuns()` at start-up sets stale `running` records to `interrupted`.

### 2.3 Store, API and events

- **`rev` rules.** `PUT` needs an integer `baseRev` and answers `409 REV_CONFLICT { rev }` on mismatch. The `rev` (and `updatedAt` / `updatedBy`) advance, and `workflow_saved` is emitted, only when the content changed: graph without viewport, name, description or app. A viewport-only save leaves `rev` untouched, so panning never disturbs other tabs. `PATCH` never changes `rev`. `POST …/runs` accepts an optional `rev`: `409 REV_CONFLICT` if it differs, `400` if not an integer; the client always sends it after flushing autosave.
- **Rename only via `PATCH`.** The `PUT` route ignores `name` (the store's `saveGraph` would accept it when called directly), so a stale tab can no longer undo a rename. `PATCH { name?, folder? }` updates the backing session title / folder and emits `workflow_renamed { name, folder, updatedBy }`; the client applies name and folder from that event.
- **Validation strictness.** Autosave (`PUT`) validates structure only (ids, endpoints, self-loops, duplicates, cycles); ports and types are checked on import and by the engine. Unknown node types are kept. `PUT` without `app` keeps the stored app and prunes references to deleted nodes; with `app`, unknown params or outputs that are not `output.result` are rejected. Limits: 500 nodes, 2000 edges, 200 groups, 200 notes, 2 MB document, 120-character names.
- **Folders.** `renameFolder` / `deleteFolder` also update the hidden backing sessions and call `store.onFolderChange` listeners; the workflow store rewrites `workflow.json`'s own copy of `folder` (rename → new name, delete → `null`). Workflows do not count as chats, so a project holding only workflows can still be deleted.
- **Response shapes the SPEC left open.** options → `{ options: [{ value, label }] }`; `DELETE` → `{ ok: true, id }`; `GET …/assets` → `{ assets: [Value + prompt + createdAt] }`; `PATCH …/results/:nodeId` → `{ selected, history }`; `cancel` → `{ ok }` (`false` with HTTP 200 if not running); `PATCH /:id` → `{ id, name, folder, rev, updatedAt }`; `GET /api/workflow-templates` → `{ templates: […] }`. `GET /api/workflows/:id` returns `activeRun` as the run id string or `null`, while the SSE `snapshot` carries `{ runId, mode, nodes: { id: status } }`.
- **Routes beyond the SPEC.** `GET /api/workflows/:id/runs?limit=` (1–50, default 10) → `{ runs: [{ id, mode, targets, force, user, status, startedAt, finishedAt, cost, error }] }`; `?accept=image|video|audio` on uploads; `?lang=de|en|es` on templates; `POST /api/workflows` accepts `templateId` + `lang` (`document` wins over `templateId`).
- **Uploads.** Raw body, `Content-Type` = MIME, header `X-Filename` (URL-encoded allowed). Extension from a MIME map, otherwise from the file name (`.jpeg` → `.jpg`); whitelist png / jpg / webp / gif, mp4 / webm, mp3 / wav / m4a / aac. Streamed to a scratch dir inside the backing session (never buffered), max 500 MB; early `413` / `415` answers close the connection after the response. An SVG (max 10 MB, read into memory) is stored like in the chat (source plus a 1024 px PNG); the response is `{ value (the PNG), rasterized: true }` and the SVG source is not offered as a port value. An SVG that cannot be rasterised, or that references local files, gives `415` and leaves nothing in the ledger.
- **Import asset.** `{ sessionId, assetId }` from any session; not found → 404, pending → `409 ASSET_PENDING`, not image / video / audio → 415. An asset already in the workflow's own session is returned without a copy.
- **Send to chat.** `GET …/send-to-chat/plan?nodeId&entry?&variant?` lists what a send would transfer (per output port: kind, media with preview url, texts shortened to 120 characters, `selected` = sent by default). `POST …/send-to-chat { sessionId, nodeId, entry?, variant?, ports?, port? }` copies up to 24 media files into the chat as uploads (more → `400`) and appends a user message with `uploadIds` and a structured `origin { kind:'workflow', workflowId, workflowName, nodeId, nodeLabel, nodeType, ports:[{id,type}], texts:[{port,text}] }`. Without `ports`/`port` a result with media sends only its media ports (side texts such as `expanded_prompt` stay out); a result without media sends its text and number ports. The chat view renders `origin` as a card (the `content` is not shown); `GET /api/sessions/:id` adds the computed `origin.canOpen` (the caller may open the workflow), so the card links to `#w=<id>` only then. Messages of the older format (`[Workflow «…»] Ergebnis «…» aus der Node-Ansicht uebernommen.`) are parsed best effort into the same card. `content` is the short German note the Director reads (workflow, node, asset ids, sent texts) and is not localised. **`409 CHAT_BUSY`** while a Director turn runs in the target chat (`brain.isTurnActive`) or while the last assistant message has tool calls without all their tool results; checked before copying and again inside `store.mutateSession`. Without it, a message inserted between `assistant(tool_calls)` and its `tool` replies breaks every later provider request of that chat.
- **ZIP.** `GET …/outputs.zip[?runId=]`: selected results of all `output.result` nodes (or the entries one run produced), ordered by canvas y then x, files named `NN-<label>[-k].ext`, text and number results as `.txt`, max 500 entries; `404 NOT_FOUND` without results.
- **SSE.** Same headers and `: ping` every 15 s as the chat stream; first frame `snapshot`, then `run_started`, `node_status`, `node_log`, `node_result`, `run_cost`, `run_finished`, `workflow_saved`, and the new `workflow_renamed`. After a reconnect the client re-reads `GET /api/workflows/:id`.

**Error codes** (`{ error, code, … }`; the extra field is in brackets):

| HTTP | Codes |
| --- | --- |
| 400 | `INVALID_ID`, `INVALID_WORKFLOW`, `INVALID_REQUEST`, `INVALID_GRAPH` (`issues`: `[{ nodeId, port?, level, code, message }]`) |
| 404 | `WORKFLOW_NOT_FOUND`, `RUN_NOT_FOUND`, `ENTRY_NOT_FOUND`, `NOT_FOUND` |
| 409 | `REV_CONFLICT` (`rev`), `RUN_ACTIVE` (`runId`), `CHAT_BUSY`, `ASSET_PENDING` |
| 413 | `TOO_LARGE` (upload > 500 MB, SVG > 10 MB, document > 2 MB) |
| 415 | `UNSUPPORTED_MEDIA` (unknown extension, wrong `?accept=`, SVG not rasterisable or with external references) |
| 429 | `RUN_LIMIT` |
| 502 / 503 | `UPSTREAM` (ElevenLabs voice list), `UNAVAILABLE` (no ElevenLabs key, no Higgsfield catalogue) |

`NODE_TIMEOUT` is an engine-internal code on the node error, not an HTTP status. Anything else answers `500` with its message.

### 2.4 Provider and Director safety

- **Node-only tools.** `higgsfield_edit` and `higgsfield_speech` are in `EXECUTORS` but not in `toolDefinitions()`. `executeTool` refuses names in `NODE_ONLY_TOOLS` unless `ctx.nodeView === true`, which only the engine's `toolCtx` sets; `extra_params` for Higgsfield generation is honoured only with `ctx.nodeView`. Reason: the Director's closed tool schema is not enforced server-side, so a model (or a prompt injection) could invent such a call. `brain.js` additionally rejects tool calls whose name is not in `toolDefinitions()`, and `executeTool` looks tools up with `hasOwnProperty`.
- **Higgsfield edit MCP arguments are nested under `params`** (`mcpCall(tool, { params: { … } })`) because `docs/higgsfield-tools.json` demands it; the SPEC table showed them flat. The exceptions are flat: `list_voices`, `media_upload`, `media_confirm`; `generate_audio_batch` takes `requests: [{ index, params }]` like the other batch tools. The job id is taken from the response without the imported source media ids. The response formats have not been verified against the live API (§2.6, §5).
- **SVG guard (`lib/svg-safe.js`).** resvg reads absolute and relative file paths from `href`, `xlink:href` and `url()`, which would let an uploaded or generated SVG pull other images from the server's disk into the PNG. Allowed targets: in-document `#id`, `data:` URIs and `http(s)://` URLs (resvg never fetches remote resources, so web fonts or links in exported logos are simply ignored); everything else, i.e. local or relative paths, is rejected, as is any `<!ENTITY`. Used centrally in `tools.storeImportedSessionAsset` (node uploads **and** the Director's import tools for GTS, branding and cast assets: an SVG with disallowed references is kept without a PNG raster, a node upload answers `415`), in `image.svg_rasterize` (`checkSvgSafe`, plus a 2 MB cap) and in branding import (`rasteriseSvg`).

### 2.5 Frontend

- **Canvas input.** Left-drag on empty canvas draws a rectangle selection (Shift adds); there is no freehand lasso. Tools: *Select* (`V`) and *Hand* (`H`). Pan with Space + drag, middle mouse, the hand tool or two-finger scroll; zoom with Ctrl / Cmd + wheel or pinch, range 0.1–2.5. Dragging from a connected input port picks up that edge: drop on another port to re-route, on empty canvas to delete (SPEC §12.4). `F` fits the selection or everything, `Cmd/Ctrl+0` resets to 100 %.
- **Routing and the `#s=` hash.** `#w=` is the list, `#w=<id>` the editor, `#app=<id>` the Design App. `app.js` rewrites `#s=` after its own init; while the node view is active `history.replaceState` is wrapped to swallow such calls and to remember the chat hash for "← Chat" (`sessionStorage` `ocd-nodes-return`). Do not rely on `hashchange` alone.
- **Focus and `inert`.** The chat stays rendered under the overlay. Entering the node view sets `inert` on `body > .app`, blurs a focused chat element and focuses the canvas; a `focusin` guard redirects the late `focus()` that `app.js` fires on the composer; leaving removes `inert` and focuses `#input`. Without this, keys typed after a reload on `#w=<id>` went into the chat composer, and ⌘↵ (run selection) could send that text as a chat message.
- **Fit and side panels.** The first fit after opening a workflow uses `padding: 48` and waits until the side-panel grid animation has ended (max 700 ms). Below 1600 px the drawer and inspector are closed for that first fit unless the user pinned them (`ocd-nodes-drawer` / `ocd-nodes-inspector` = `1`); the inspector reopens on selection. In the list view the drawer is always open; in the editor it starts open from 1360 px width unless a saved choice says otherwise.
- **Persistence.** Autosave 800 ms after a change (1600 ms for viewport-only), flushed before runs and on leaving; `keepalive` is used only for bodies under 60,000 characters (browsers refuse larger ones). The workflow list reloads whenever the node view is activated and a workflow opened by hash is added to it. Node ids are never reused within a workflow (the `reserved` set), because `results.json` keeps ids of deleted nodes. Any foreign `workflow_saved` shows the conflict banner (reload / keep mine), even without local changes.
- **Dialogs.** No native `alert` / `confirm` / `prompt` (test-guarded). The paid-run confirmation focuses "Cancel" and Enter does not confirm. Deleting a workflow says that its files are deleted too.
- **Run UX.** The plan is re-fetched after a save that changed `rev` while no run is active, after a run ends and after a variant change. SSE is primary; a 4 s poll of `GET …/runs/:id` is the safety net. Cancel warns only if a paid provider job is in flight; submitted provider jobs still finish and cost money. Card previews show up to 12 list cells plus "+N". No per-run detail view, no "retry all failed".
- **Design App.** Form values are sent as `overrides` of a `mode: 'all'` run; the saved graph is never changed. `force` is set only when a fresh plan says everything is cached ("Run again"). Batch = a list input (`input.text_list` / `input.media_list`); the counter under the list mirrors the server's `parseTextList` (a test checks parity).
- **Templates.** Each `lib/nodes/templates/<id>.json` is an export document plus `id`, `requires` (subset of `openrouter`, `ffmpeg`, `elevenlabs`, `rendernode`, `higgsfield`; the last is met when Higgsfield is connected) and an `i18n` block. English is the base text of the file; the block holds `de` and `es` overrides with keys `name`, `description`, `node.<id>` (title), `note.<id>`, `group.<id>`, `param.<node>.<param>`, `app.title`, `app.description`, `app.input.<node>.<param>`, `app.output.<node>`. Every template ships with an enabled Design App; `validateTemplate` checks types, ports, edges and the app section. Templates whose `requires` are not met are listed as unavailable with the missing reasons. `GET /api/workflow-templates/:id?lang=` returns `{ document }` (name, description, graph, app) and applies the same role filter as the list (participants and guests get 403 for templates with restricted node types, as does `POST /api/workflows` with that `templateId`). The gallery and the palette tab «Vorlagen» can create a new workflow or insert the graph into the open one: `graph.insertSubgraph(graph, sub, { at, center, avoid, reg, sizes, reserved })` gives new ids, places the block right of or below the existing content (centred on an empty canvas) and returns the ids it created; `OCD.editor.insertSubgraph` wraps it in one undo step, selects the new items and does not take over the template's `app` part. Nothing is run.
- **i18n.** All node-view strings live in `public/nodes/i18n-nodes.js` as rows `[key, de, en, es]` (Swiss spelling, no "ß" in any language). `test-nodes-i18n.js` requires a translation for every registry type, category, port, param and non-numeric select option.

**How it is built**

- **Edit tools as specs.** The entries of `HIGGSFIELD_EDIT_TOOLS` are `{ sources(kind), output(kind), build(mediaIds, params, kind) }` (the five older tools behave as before). `runHiggsfieldEdit` checks the number and kind of the sources (motion transfer takes image, then video), then dry-runs `build` with placeholder ids, so invalid params (enums from the tool schemas, empty `voice_id`) fail **before** anything is uploaded or imported. Keys the schema does not know are dropped (`additionalProperties: false`). `excludeIds` for the job id are all imported media ids.
- **Voice params.** `voice` is a select fed by the option source `higgsfield-voices`; its values are `<voice_type>:<voice_id>` (`preset` or `element`), its labels the voice name plus the gender when there is one. `voice_custom` is a text fallback that wins over the list (a bare id is a preset, `element:<id>` an own voice), so a voice can be given while the list cannot be loaded (the inspector keeps the current value when an option source fails). `parseVoiceParam(selected, custom)` in `nodes-generate.js` reads both. A missing voice is a validation error before the run.
- **Speech (`higgsfield_speech`, node-only).** Only `seed_audio` and `text2speech_v2` run (the node offers exactly these two; the tool refuses any other model). One `generate_audio_batch` request; the result is WAV by default. Everything below is checked before anything is imported or submitted (German messages from the tool, English ones from the node's plan check):
  - `voice_type` and `voice_id` are sent together or not at all; the raw fields are reserved in `extra_params` (the voice comes from the voice params) and hidden from the model description of the two models.
  - `seed_audio` needs a voice or a reference audio and takes 0..2 reference audios, passed under the model's audio role (`medias` entries with `role`). The role is the first one containing "audio" in the `roles` of the model (`audioSlotFromModel`; never the slot type). If the model cannot be read at all the documented `audio_references` is used; a readable model without an audio role fails. A limit stated by an audio-only slot is enforced as well.
  - `text2speech_v2` needs a voice and a `variant` from the list above (in `extra_params`; checked before the model is read and once more after the whitelist, which may drop a variant the model does not define) and takes no reference audio.
  - `extra_params.format` may only be `wav` or `mp3`; `pcm` and `ogg_opus` are refused with a clear message (the app cannot play them), and the inspector does not offer them (`describeModel` filters the `format` options of audio models). Other model parameters (`sample_rate`, `speech_rate`, `pitch_rate`, `loudness_rate`, …) use `extra_params` + `applyHiggsfieldExtraParams` exactly like the generation nodes; the whitelist reads `integer` and `number` parameters (min / max, options) and accepts a number for a string option such as `"24000"`.
  - The job goes through `submitHiggsfieldJob` (kind `audio`, `mode: higgsfield_audio`) with the same duplicate-job-id protection.
- **Audio input of `video.higgsfield`.** `runHiggsfieldGeneration` passes `reference_audio_asset_ids` only with `ctx.nodeView` (the Director cannot). `importHiggsfieldReferences(ctx, modelId, outputKind, rawIds, rawAudioIds)` refuses audio without an image (or video) reference, reads the roles from the model once, checks the audio role and its limit before importing anything, and maps images and audio to their roles (documented `audio_references` when the model cannot be read at all). Up to 15 tracks are accepted by the node; the model's own limit is used when an audio-only slot states it (a slot shared with image roles does not, so Higgsfield decides then). Media slots whose roles are all audio roles no longer count as image reference slots (`models_explore` types every slot as `image`). The node's `version` was **not** bumped: without an audio input identical inputs give identical results, and the cache key only contains connected inputs, so cached paid results stay valid.
- **Upload without `PUBLIC_BASE_URL`.** `importHiggsfieldMedia` still publishes and imports by URL when `PUBLIC_BASE_URL` is set. Otherwise `uploadHiggsfieldMedia` runs, per source: `media_upload { filename, content_type }` → `PUT` of the file to the returned `upload_url` (`fetch`, streamed, explicit `Content-Length` and `Content-Type`, 10 min limit, 500 MB cap) → `media_confirm { type, media_id }` → media id. Types by extension: png jpg jpeg webp gif, mp4 webm, mp3 wav m4a aac. `parseHiggsfieldUpload` accepts JSON, JSON inside prose and plain text (a labelled `upload_url`, a curl `PUT` line or a single https URL, plus the media id). The signed URL is a credential: it appears only in the PUT call and never in an error message or log (`redactUrls`, S3 error bodies reduced to their `<Code>`); only https upload URLs are used. Effect: the `hf.*` nodes no longer depend on `PUBLIC_BASE_URL`, and the reference warning of the Higgsfield generation nodes is gone. Seedance video / audio references (OpenRouter) still need it.
- **Audio results.** `submitHiggsfieldJob` accepts `kind: 'audio'` and reserves the result asset as `.wav` (ledger kind `audio`). The poller picks the real extension in `higgsfieldResultExtension` (audio MIME type first, then the URL ending; `.mp3 .wav .m4a .aac`), with `.wav` as the fallback for audio, and renames the asset; further results of one job become extra audio assets.
- **Voices.** `listVoices()` calls `list_voices { size: 100, cursor? }` through `mcpCall(name, args, { withStructured: true })` (a minimal option of `lib/higgsfield.js`: it resolves `{ text, structured }`, the default stays the plain text) and pages through `structured.next_cursor` for at most 5 pages (it stops on `has_more: false` or a repeated cursor). It de-duplicates by value, caches for 60 min together with the models (`clearCache()` clears both) and returns `[]` while Higgsfield is disconnected; an error answer throws and is not cached. `parseVoices(text, structured)` prefers the structured part and falls back to JSON in the text and finally to one voice per line (`voice_id=…, voice_type=…`); both spellings `voice_id` / `voice_type` and `id` / `type` are read. `GET /api/nodes/options/higgsfield-voices` returns `{ value: '<type>:<id>', label: 'Name (gender)' }`; a failing list answers `502 UPSTREAM`. ### 2.7 fal.ai (MiniMax H3 Max)

Status 2026-09-29: built and tested against mocks only; **not verified against the live fal.ai API** (no paid call was made), apart from the one endpoint listed under "Live verified 2026-09-30" below. The 15 public endpoint schemas and list prices in `docs/fal-h3-max.json` (fetched the same day) are the source for every field name and enum. All nine node types are category `fal` (after `higgsfield`), `experimental`, `paid` (USD), `async`, and available as soon as `FAL_KEY` is set.

**Connection.** `FAL_KEY` is a setting like `ELEVENLABS_API_KEY` (`lib/settings.js`, `.env.example`, the generic key list of the settings dialog; `GET /api/config` carries `fal: { enabled }`, never the key). Requests use the header `Authorization: Key <FAL_KEY>`, the key is read at call time. No error message, log line or job field contains the key or a signed URL (`FalError` messages are cut at 300 characters and every URL is replaced by `[URL]`).

**Upload.** fal only accepts URLs, so session assets are uploaded first (`lib/fal.js` `uploadFile`): `POST https://rest.fal.ai/storage/upload/initiate?storage_type=fal-cdn-v3` (`{ content_type, file_name }`, header `X-Fal-Object-Lifecycle: {"expiration_duration_seconds":86400}`) answers `{ upload_url, file_url }`, then the bytes are streamed with `PUT upload_url` (`Content-Type`, `Content-Length`). Both URLs must be https; `file_url` goes into the model input. The official client switches to multipart at 90 MB; this app does not, so a file over 90 MB is refused with a clear message before any request. An asset that is used twice in one job is uploaded once.

**Queue and poller.** The node-only tool `fal_generate` (`NODE_ONLY_TOOLS`, never offered in the chat) takes `{ endpoint, input, media: [{ field | placeholder, assetIds, multiple }], kind, estimateUsd, pricing, keepResult }`. Order: key, endpoint id (`isValidEndpointId`), input and pricing shape, session assets (own session only, finished, image / video / audio extension, at most 30 files, each at most 90 MB), then the sequential uploads, then `POST https://queue.fal.run/<endpoint>` (header `X-Fal-Object-Lifecycle-Preference` keeps the result 7 days). Nothing is uploaded or queued unless every check passed; a failing submit removes the reserved asset again. The answer's `status_url` / `response_url` must start with `https://queue.fal.run/` and are stored on the job (they are authoritative for nested endpoint ids). The job is a normal `session.jobs` entry: `source: 'fal'`, `jobId` = request id (duplicate request ids are refused like duplicate Higgsfield ids), `endpoint`, `statusUrl`, `responseUrl`, `kind` (the reserved ledger kind: `.mp4` / `.png` / `.mp3`, `auto` reserves a video), `resultKind` (what the node asked for, incl. `auto`), `timeoutAt` (90 min), `costEstimateUsd`, `pricing`, `keepResult`.

The poller (`pollFalJob`) asks `GET status_url` every round: `IN_QUEUE` / `IN_PROGRESS` only update the job state (`queued`, `in_progress`); `COMPLETED` with an `error` fails the job; `COMPLETED` fetches `response_url`, picks the medium with `extractMedia(result, resultKind)` (video: `video.url` or `videos[0].url`; image: `images[0].url` or `image.url`; audio: `audio.url`, `audio_file.url`, `audio_url`; `auto` = first hit in that order), streams it with `downloadToFile` (https, hosts `fal.media`, `*.fal.media`, `*.fal.run`, `*.fal.ai` only, redirects re-checked, at most 1 GB, partial file removed on failure) into a temp file inside the session asset directory and moves it into the reserved asset (`completeAssetFile` with the real extension and kind). No medium in the result fails the job. HTTP 401 / 403 / 404 / 422 and other non-retryable answers fail the job with a clear message; network errors, timeouts, 408, 429 and 5xx leave it open until the 90 minutes are over (`fal.ai-Job hat nach 90 Minuten das Zeitlimit erreicht.`). Without a key the poller skips fal jobs. The job keeps small metadata: `seed`, `expanded_prompt` (2000 characters), `duration`, and for the free node `resultJson` (50 KB).

**Prices** (`PRICES` in `nodes-fal.js`, source `docs/fal-h3-max.json`, fetched 2026-09-29): the **list prices after the launch discounts end on 2026-09-30**, USD per generated second. H3 Max (video, reference, camera, extend, 3D) 480P 0.05 / 768P 0.08 / 1080P 0.16 / 2K 0.32 (2K only extend and lip sync); Turbo 0.025 / 0.04 / 0.08; lip sync as H3 Max, ×1.2 above 15 s; insert scene 480p 0.05 / 768p 0.06 (only the new scene); styles 0.08. Until 2026-09-30 fal charges half, so the estimate is too high before that date. `estimate(params)` = duration × price wherever the duration is a param; 3D knows its duration only from the connected media (measured with ffprobe in `execute`; 3D bills at least 5 s), the free node has no estimate. The lip sync is priced by the plan from the audio it would receive (`context.inputs.audio`, as `fal.video_segment` does with its video): `lipsyncUsd(params, seconds)` is the function of the run too (list price of the resolution × seconds, ×1.2 above 15 s); for a list the plan gets the mean price per item, so that its total (mean × runs) is the sum; a clip without a length (an upload) or an audio that is not there yet (`inputs` is empty until everything before the node is up to date) make it unknown (`null`); `cost.history: false`, so the last run of another audio is never shown as the price. Not estimated: reference tokens above the free 4096-token allowance (reference, extend, insert, 3D) and the reference images fal generates for 3D. The booked cost of a finished job is `duration × perSecond` when the result reports a duration (lip sync: `duration`, insert: `injected_duration`, others none; extend ignores it because it may include the source clip), otherwise the estimate. It goes to the ledger, the job and the cost journal (type `fal`, billing "Schaetzung (Listenpreis)") and is marked as an estimate (`~$` in the chat message). fal reports no price.

Fields are built exactly as the schemas name them: empty options are left out, `sync_mode` is never sent, resolution enums keep their spelling (`480P` upper case except `insert-video`), the prompt expansion is `prompt_expansion_mode` (`disabled` / `balanced` / `quality`) for video / reference / camera and the boolean `enable_prompt_expansion` for extend and insert, safety is `enable_safety_checker`. **Camera presets** (keyframes `{ time, azimuth, elevation, distance }`, start `{0, 0, 0, 1}`): `orbit_left` / `orbit_right` azimuth −90 / +90, `orbit_360` +360, `dolly_in` / `dolly_out` distance 1 → 0.5 / 1.5, `crane_up` elevation 0 → 30, `crane_down` elevation 30 → 0 (the only preset that does not start at elevation 0). **Free node.** `input_json` is parsed first; the placeholders are replaced in the **parsed** value, never in the text: a string value that is exactly `{{image_1}}`, `{{video_2}}` or `{{audio_1}}` becomes the uploaded URL of that connection (1-based, in connection order), `{{images}}` / `{{videos}}` / `{{audios}}` the list of URLs, and `{{prompt}}` inside a string is replaced by the prompt text (a `$` in the prompt is literal; the inserted text is not scanned again, so a prompt cannot inject JSON or media references; object keys are never rewritten). A media placeholder that is not the whole string, or that points past the connected media, is an error before anything is uploaded; only referenced media are uploaded. The tool receives sentinels (`@@fal:image_1@@`) and swaps them after the upload. The result JSON (from `keepResult`) is cut at 50 KB and returned as the `json` text.

Category `input`, output `prompt` (`text`), one inline `textarea` param `prompt`, executes like `input.text`. The palette pins it to the top of «Inputs» (`rankPaletteEntries`), and a search for "prompt" ranks it before "Text input". ### 2.9 Port hover help and visible multi-inputs

Feedback: nobody could tell what a port such as *Images*, *Prompt* or *Expanded prompt* expects, and it was not visible that an image or video model takes more than one reference. Four additions, no server change.

- **`graph.describePort(reg, graph, nodeId, 'in' | 'out', portId)`** (pure, UMD, tested) returns a structured description, no strings and no HTML: `label` / `labelKey`, `base` / `typeKey` / `list`, `required` (inputs: boolean, outputs: `null`), `multiple` / `max` / `count`, `text` (the lookup keys, below), `facts` (`[{ key, vars }]`) and `connections` (`[{ order, edgeId, nodeId, nodeTitle, titled, nodeType, port, multiOutput }]`, at most `PORT_TIP_MAX_CONNECTIONS` = 5, the rest as `moreConnections`). - **Tooltip** (`port-tip.js`, `.nv-porttip`). One tooltip for the whole port row (dot and label) instead of a native `title`; it is created by the canvas (`createPortTip`), lives in `ui.root()` (`position: fixed`, outside the zoomed `nv-world`) and therefore has the same size at every zoom (300 px wide at most, 12 px text). ### 2.9a Order of the connections of a multi-input (WP36)

Problem: *Edit image* takes up to 8 images and a prompt says "Image 1", "Image 2", but nothing showed which connection is which. The badges of an input all sat on one point, so only the highest number was readable and looked like a count. No server change; the engine already collects a multi-input in `graph.edges` order (`resolveNodeInputs`) and the fingerprint of a list keeps the item order, so a new order gives a new cache key (checked in `test-nodes-engine.js`).

- **Numbers on the edges.** `edge-geometry.js` (pure, tested in Node): `path` is the curve the canvas always drew; `table(a, b)` samples it with arc lengths; `placeBadges(curves)` puts each badge `BADGE_OFFSET` (48 px) back from the input along its own curve and moves it further back in 6 px steps until it covers no earlier badge of the input (at most 85 % of the curve). Edge cases: identical curves are nudged sideways, a curve too short for the offset takes its middle, backward and straight-above edges work because the distance is along the curve. The canvas places an input together and again when one of its edges moved or its connections changed (`entry.signature`). The number comes from `graph.connectionOrder` (the loop `describePort` used before, now shared): behind the first list connection it is "…" (dashed ring for the list itself), a single edge has no badge.
- **Row under the input.** `canvas.orderRowsFor` builds, per multi-input with two or more connections, the sources in engine order (title of the source, output name when it has several, preview: first image of the source's slot preview, else the file of an input node). `ui.applyOrder` draws it (`.nv-node-order`): small previews for image inputs (placeholder with the title until there is a result), numbered chips with the title for other types, the same numbers as on the edges; the native `title` of a chip names source and output. The row is rebuilt only when its content changes and waits while a chip is being dragged.
- **Changing the order.** Drag a chip (pointer events, nearest chip is the new place, Esc or cancel keeps the order), arrow keys / Home / End on a focused chip, or the context menu of a chip or an edge (first, one earlier, one later, last). All go through `main.reorderInput` -> `graph.moveInputEdge` / `setInputOrder` (pure: only the slots the input's edges hold in `graph.edges` are reassigned, everything else keeps its place; errors `unknown_node`, `unknown_port`, `not_multiple`, `unknown_edge`, `bad_target`, `bad_order`) -> `applyGraph(..., { history: 'reorder-inputs' })`: one undo step, autosave, the next plan marks the node stale. The node view does not lock graph edits during a run (connect and disconnect are not locked either), so reordering is not locked.
- **Texts.** `nodes.order.*`, the facts `nodes.porttip.fact.order` / `orderImage` in `describePort` (from two connections on, not for inputs that take one), and the first tip of *Edit image* and of the H3 Max reference node say that "Image 1", "Image 2" are these numbers and how to change them. de / en / es.
- **Tests.** `test-nodes-order.js` (geometry, reorder, numbering, undo, the row with a small DOM stand-in: keys, menu, drag, focus), `test-nodes-engine.js` (engine order and cache invalidation), `test-nodes-graph.js` / `test-nodes-i18n.js` / `test-nodes-help.js`.
- **Not checked in a browser.** The DOM code was exercised with a stand-in only; the look of the row and the badge placement on real curves have not been seen on screen.

### Palette search (WP21)

- **What is searched.** Each entry keeps its parts apart (`graph.paletteEntry`): the names (translated and English), the synonym phrases (`nodes.type.<type>.keywords` in the interface language, then the registry's English `keywords`) and the rest (category, type id, `description`). A hit in a name scores 100 (word start) or 60 (inside a word), in a synonym 90 or 50, in the rest 40 or 20. All words of the query must match; words like "zu", "to", "a" only glue a phrase together and need not match alone. One word that equals a name ("prompt" for "Prompt") earns +20, so that node leads the nodes whose name merely starts with it. The whole phrase earns a bonus: in a name 100 (equal) or 60, in a synonym up to 80 (equal; each position in the list costs 2, so list the important phrases first) or 45. Accents and case do not matter (`normalizeSearch`).
- **Scattered letters** ("sedance" for "seedance") match only a name, only from a word start, only with 4 or more letters, and only while fewer than 3 entries match for real.
- **Order.** Score, then the quick-pick rank, then nodes before models, then usable before unavailable, then generators before editors before helpers (`nodeRole`: tool categories `input`, `text`, `utility`, `output` are helpers, `edit-*` and media nodes that need a media of their own output kind are editors), then the name. Without a search text the same rule orders each category.
- **Models** (Higgsfield) never crowd nodes out: they have their own limit (30, or 90 in their own chip), the rest is returned as `results.hiddenModels` and shown as "+ N more models". Without a search text there are none in "All" and none in the quick pick.
- **Quick pick from an image or text output.** From an image, nodes that make a video of it come first (generators rank 5, a local one such as the still image zoom 4, image editors at most 3). From a text, the generators of video and of images share rank 4 ("Generate image", the usual next step after a prompt, stays among the first entries); helpers that merely take text stay at 3. Nodes that also need a video of their own (overlay, extend, motion transfer) get no boost.
- **Unavailable.** The server's reasons are translated (`ui.availabilityReason`, `nodes.reason.*`), unknown ones are shown raw.
- **Fresh availability.** `graph.createRegistryWatcher` fetches `GET /api/nodes/registry` again when the tab becomes visible, the window gets focus or the view is opened again, at most every 15 s and never in the background. When the availability of any type changed, `main.js` (`applyFreshRegistry`) swaps the registry and refreshes the palette, the run buttons and the Higgsfield option lists, rebuilds only the cards of types whose availability changed (a field the person is typing in keeps its focus) and renders the inspector again only when a selected node is of such a type and no field of the inspector has the focus (otherwise as soon as the focus leaves). The design app view only receives the new registry; it shows no availability.
- **The still image zoom** (`image.to_video`, a local Ken Burns zoom) is called "Standbild-Zoom (lokal)" / "Still image zoom (local)" / "Zoom de imagen fija (local)"; the type id is unchanged so saved workflows run as before. Its name and synonyms deliberately leave out "image to video", "animate" and "AI" (not even as "no AI": a search for "ki" / "ai" / "ia" would then find exactly this node); the "no AI" hint sits in the tooltip of its image input.

Test: `scripts/test-nodes-search.js` (golden queries in DE / EN / ES as participants and as admin, 1000 models, quick pick, noise, ties, rename, old workflows, reasons, watcher) and `scripts/test-nodes-graph.js` (`testSearchRules`).

### Reference limits per model (WP31)

- **One mechanism.** A multiple input may declare `limitBy: { param, capability }` (`capability`: `references` or `audio`) and the definition then needs `limitsFor(params)`, which answers `{ known: true, max, roles?, required?, subject? }` or `{ known: false }`. `registry.portsFor` (server) and `graph.portsFor` (client, resolver injected through `indexRegistry(payload, { limitsFor })`, so `graph.js` stays pure) add `port.limit` and lower `port.max` to the model limit; the fixed `max` of the port (12 references, 15 audio) stays the ceiling. An unknown limit is never shown as 12: the badge shows the count only.
- **Capabilities.** `higgsfield-catalog.capabilitiesOf(model, { type })` reads `medias` (sum of the image slots, capped at 12, roles, required) and the audio slot. `describeModel` and the option lists (`/api/nodes/options/higgsfield-*-models`) carry `references: { max, roles, required }` and, for video, `audio: { max }`; both are `null`/absent when the catalogue does not say.
- **Refusal and validation.** `checkConnection` refuses over the limit with `{ code: 'too_many', data: { port, max, count, model } }` (toast through `ui.connectText`). `validate` answers `too_many_refs` / `refs_required` with `data: { model, max, count }`; the plan node carries `reasonCode/reasonData/reasonPort`, `run.js` shows the text on the card, `start()` rejects such a graph with `INVALID_GRAPH` before any submit. The execute check stays as the last safeguard.
- **Model change.** `pruneEdges` does not remove over-limit multi inputs: the connections stay, the node is invalid with a readable message and a toast is shown once (`noticeModelLimits`). The inspector select marks models that do not fit the current connections (they stay selectable).
- **Cold or expired catalogue.** `validate` reads the catalogue cache without I/O. A definition may therefore declare `prepare(params)`; the engine calls it for the nodes that will run before every plan and every start (in parallel, 10 s at most, `limits.prepareTimeoutMs`; failures and timeouts leave the data unknown and never fail the plan; not for restricted nodes of a participant). The Higgsfield nodes load their model there, so a run that exceeds the references of the model is refused before any upstream paid node runs, also after a restart or after the one-hour TTL of the catalogue.
- **Client cache.** `ui.modelDetail` fetches one model description per id (shared by inspector, card and tooltip); on arrival the canvas and the plan are refreshed. A description older than 20 minutes is read again in the background (the old one stays in use; a failed refresh keeps it) and before every run. A failed read marks the limit as unknown for good (`limit.error`, tooltip "could not be read"), not as "still loading".
- **Other nodes.** `hf.speech` with `text2speech_v2` takes no reference audio (`portVariants`, fixed max 0); a fixed maximum counts as a limit on the card and in the tooltip (`2/0` is an error). `video.seedance` has the input limits of Seedance 2.5 (30 / 10 / 10); the configured video model decides what is really taken (`video-models.referenceLimits`: 9/3/3, Wan 5/0/0, Kling and Veo 0), and `execute` refuses before anything is sent. The limits on the card do not follow the configured model yet (no model param on the node; the configuration is not part of the registry view).
- **Test.** `scripts/test-nodes-limits.js` (graph, ui helpers, texts in three languages) and the WP31 section of `scripts/test-nodes-generate.js`.

### Videos side by side (WP28, part 3)

- **Node.** `video.grid` ("Videos side by side", category `edit-video`, local, no cost): input `videos` (multiple, 2 to 4, `min: 2`), optional text input `labels` (bound to the param `labels`, one line per video in the order of the connections), output `video`. `execute` takes `inputs.labels` when connected and the param otherwise. A count outside 2 to 4 is the issue `grid_videos` (`data { min, max, count }`) before the run and an error in `execute`.
- **Layout.** `planVideoGrid` (lib/nodes/ffmpeg-ops.js) is a pure function of the probes: `layout` auto = next to each other for two or three videos, 2 × 2 for four; `grid` with three videos leaves the last place empty (background colour). Every video keeps its aspect ratio: `match` height (default for rows and grids) or width (default for stacked) makes that side equal, the other side follows the ratio; a slot is as wide as the widest video of its column and as high as the highest of its row, each video sits in the middle of its slot. `size` 0 = the smallest video decides (no upscaling); the canvas never exceeds 4096 pixels on a side (the edge shrinks by a tenth until it fits). All sizes, offsets and the gap are even (yuv420p). Nothing is cropped or stretched.
- **Length and sound.** `length` longest: the canvas runs as long as the longest video and `overlay` repeats the last frame of the shorter ones (`eof_action=repeat`); shortest: everything ends with the shortest. The result runs at the highest frame rate of the videos (at most 60). `audio` none (default) or the sound of the first video (`apad`, cut at the end); a first video without sound gives a result without sound, not an error.
- **Labels.** Each label is a pill (white text, dark half-transparent bar) drawn with resvg like `image.text_render`, measured with `getBBox`, written as a PNG into a scratch folder and passed to ffmpeg as one more input; the filter graph scales it to a tenth of the video height (`font_size` 0) or 1.5 times `font_size`, and shrinks it to fit the video width. `label_position` bottom or top. At most 80 characters per label, one line. Without labels resvg is not needed; with labels and no resvg the node stops with a clear message.
- **Tests.** `scripts/test-nodes-video-grid.js`: the layout as a pure function, the filter graph, and real ffmpeg output from small lavfi videos (2, 3 and 4 videos, the arrangements, mixed sizes and ratios, labels, longest and shortest, no sound and the sound of the first video, an engine run).

### Music and song text with ElevenLabs (WP30, server side)

- **Module.** `lib/elevenlabs.js`: `composeMusic({ prompt | compositionPlan, lengthMs, instrumental, modelId })` (MP3, `mp3_44100_128`) and `planMusic({ prompt, lengthMs, modelId })`. The API takes the length and `force_instrumental` only with a description, so the module refuses them next to a plan (`MUSIC_BAD_ARGUMENT`, before any request). Models `music_v2_5` (default: the newest, documented with description and plan), `music_v2`, `music_v1`; `model_id` is always sent. The timeout of a song is 90 s plus its length, at most 300 s: fetch of Node 22 (undici) ends a request by itself after 300 s without an answer (`headersTimeout`, measured: `fetch failed` with `cause.code` `UND_ERR_HEADERS_TIMEOUT` after 302 s), so a longer value would never take effect. That ending and the other timeouts of fetch (`UND_ERR_BODY_TIMEOUT`, `UND_ERR_CONNECT_TIMEOUT`) are reported as `ELEVENLABS_TIMEOUT`, too. A song that ElevenLabs needs more than 300 s for therefore ends with that code; moving the music call to `node:https` (own timeout, up to the 12 minutes a node may run) is the way out if it ever happens. Speech and plan keep 60 s.
- **Errors with a stable code** (`ElevenLabsError`: `code`, `status`, English `message`, German `messageDe`, `data`): `MUSIC_SUBSCRIPTION_REQUIRED` (music endpoints only: HTTP 402, or 401/403 whose text points at the plan), `MUSIC_PROMPT_REJECTED` (`bad_prompt`, `data.suggestion` = `prompt_suggestion`), `MUSIC_PLAN_REJECTED` (`bad_composition_plan`, `data.suggestion` = the suggested plan as readable text), `ELEVENLABS_RATE_LIMITED` (429), `ELEVENLABS_QUOTA_EXCEEDED`, `ELEVENLABS_KEY_REJECTED` (401), `ELEVENLABS_MODEL_REJECTED` (speech only, `data.model`: `model_not_found`, `unsupported_model` or `model_access_denied` of the error list, or a 422 that points at `model_id`), `ELEVENLABS_TIMEOUT` (`data.seconds`), `ELEVENLABS_SERVER_ERROR` (5xx). They apply to speech and voice list too, except the subscription code; for those (scope `api`) `message` is the German sentence, as before, for the music nodes it is English and the interface translates by code. Everything else keeps the old plain message. The key never appears in `message`, `messageDe` or `data`. Docs name only `bad_prompt` and `bad_composition_plan`; the HTTP statuses of the others are not documented, so the classification uses status and text.
- **Plan format.** `public/nodes/music-plan.js` (UMD, pure; `window.OCDNodes.musicPlan`, loaded before `graph.js`): `parse(text, { model })` → `{ plan, errors, positions }` (with a model the errors that only apply to its shape are included, with line numbers), `stringify(plan)`, `validate`, `toApi(plan, model)`, `fromApi(answer)`, `parseDuration`, `LIMITS`, `MODELS`. Errors are `{ code: 'MUSIC_PLAN_*', line, data, message }` (English fallback); the interface text is `nodes.issue.<code>` with `{line}` and the values of `data`. Model `music_v1` has global styles and sections; `music_v2` and `music_v2_5` have chunks only (text `[Name]` + lines, `positive_styles`, `negative_styles`). Chunks have no global styles, so `toApi` puts them in front of the styles of the first chunk and `fromApi` reads a chunk plan without global styles (the first section then carries them). For chunk models the section line `[Name]` is one of the 30 lines a chunk text may have, so a named section may have 29 song lines (`MUSIC_PLAN_LINES_MAX_CHUNK`), and a section without a name whose first song line starts with `[` is refused (`MUSIC_PLAN_NAME_NEEDED`: ElevenLabs would read the line as the name). Everything else is lossless in both directions. Lines starting with `+ - [ \` are written with a leading backslash.
- **Tools** (`lib/tools.js`, `NODE_ONLY_TOOLS`, not in `toolDefinitions()`): `generate_music` (also in `PAID_TOOLS`; `toolEstimateUsd` = minutes × `ELEVENLABS_MUSIC_USD_PER_MIN`, default 0.20; books a cost of type `music`, `billing: 'Schaetzung (Dauer)'`, model `elevenlabs/<model>` for every person) and `plan_music` (free, no booking). No role lock: participants and guests may use both; a guest has no budget, so `generate_music` stops at `BUDGET_EXHAUSTED`. `generate_speech` books its estimate for every person now (was: participants only).
- **Nodes** (`nodes-generate.js`): `audio.music`, `audio.music_plan`; `audio.tts` is paid now. Their prices cannot be guessed from an earlier result: `cost.history: false` in the definition. `cost.estimate(params, { connected, nodeId, ... })` is told which inputs are connected (an input through a connection has no value at plan time: unknown, never 0). `cost.unit: 'free'` (registry) marks a provider call without a charge.
- **Run errors with values.** The engine passes the flat `err.data` of an error with a stable code (upper case words) on `node_status` events and in the run record (`data`), next to `code`.
- **Costs.** `costs.js` knows the type `music`. The cost overview and the monitoring show `speech` as “Speech” and `music` as “Music” (`costs.speech`, `costs.music`).
- **Tests.** `scripts/test-music-plan.js`, `scripts/test-elevenlabs-music.js`, the music section of `scripts/test-nodes-generate.js`, the music and run parts of `scripts/test-teams-api.js`, the estimate part of `scripts/test-nodes-engine.js`.

### Music video from a song (WP34)

- **What it is.** Four nodes and the template `music-video` (SPEC §5.6, §5.9, §15). The pieces that can be computed are computed here, deterministically; the model only writes words. Nothing in the repo calls a provider in a test: ElevenLabs, the language model and the three provider nodes of the template (image, video - `fal.h3_video` for the story clips -, lip sync) are replaced.
- **Story clips: H3 Max turbo, not Seedance.** The first version of the template made the story clips with `video.generate` (the video model of the settings, 480p). The template puts the person of the reference photo into every story image, and Seedance refuses images that may show a real person (`VIDEO_REAL_PERSON`, "Item 2 of 6: Seedance rejects images that may show a real person"; the live test below), so with the default model the run failed. Node `n10` is therefore `fal.h3_video` with `model: turbo`, `resolution: 768P`, `duration: 5` (the clip length of the plan; H3 Max makes 5 s at least, the plan accepts 2 to 10), `aspect_ratio: 16:9` (ignored with a first frame: the clip follows its image), `prompt_expansion: balanced`, `safety: true`; list price 0.04 USD a second, 0.20 USD a clip. The edges are the same (`n8.image` -> `first_frame`, `n5.story_motion` -> `prompt`, `video` -> `n12.story`) and `requires` did not change (OpenRouter for the plan and the images, fal for the clips and the lip sync). In the node the model can be switched to `max` or the resolution to 1080P; "Generate video" with another model still works for scenes without people. Tests: the template test pins type, params and the 0.20 USD, `test-nodes-fal.js` runs the node with the params of the template (endpoint `minimax/h3-max-turbo/image-to-video`, price), `test-nodes-music-video.js` runs the template through the engine with a double of this node and checks that the plan prices the clips once the plan node has run.
- **Live test 2026-10-03 (paid, isolated instance).** A 30 s excerpt of a song, a fictional photorealistic portrait as the reference photo, the template as shipped then. The plan made 7 scenes (6 story, 1 singer of 5.16 s). The story clips with Seedance (2.0 fast; 2.5 is the default of the settings) stopped with `VIDEO_REAL_PERSON`. MiniMax H3 accepted the same portrait: the lip sync (480P) and the six story clips with `fal.h3_video` turbo at 768P ran through (the six clips in about 40 s), the cut came out at 1280x720, 25 fps and exactly 30.000 s, the lips visibly in sync with the song. Costs: times 0.0033 USD (Scribe), plan 0.0135 USD (language model), 8 images (Nano Banana Pro) 1.08 USD, lip sync 480P 0.258 USD, 6 clips H3 turbo 768P 1.20 USD, in all 2.56 USD. Not tried live: a full song (up to 50 scenes), the model max, 1080P, whether the safety checker of fal ever refuses a portrait.
- **Lists and empty lists.** The plan gives four lists, one entry per scene of its kind, in scene order (`story_prompts`, `story_motion`, `performance_prompts`, `performance_audio`); the engine's implicit map runs the image, video and lip sync nodes once per entry, zipped by index, and the cut gets the finished clips as two lists. A list may be empty (a share of 0, a song without words or without lyric times): the nodes behind it run zero times, give empty lists, and the cut takes an empty `performance` list as "no singer scene". The plan never leaves a list out. The two sides are tied by the number of clips: `music_video.edit` compares it with the plan before it cuts (`MUSICVIDEO_STORY_MISMATCH`, `MUSICVIDEO_PERFORMANCE_MISMATCH` with `{ expected, got }`). A list is at most 50 entries, hence at most 50 scenes: the plan raises the length of the story scenes above `clip_seconds` where a longer song would not fit and says so in the log (`SCENES_LONGER_THAN_CLIP`); a song of more than about four minutes needs a longer clip length in the plan and in the video node.
- **The singer.** The lip sync takes 5 seconds of sound at least, so a singer scene is a window of sung lines of 5.05 to 10 s (a window is extended into the pauses next to it when the lines are shorter), at least 70 % sung, preferably in a chorus and in the loud parts, spread over the song. The slice of the song of each window is cut in the plan node itself (ffmpeg, WAV, to the sample, scratch dir removed afterwards) and stored as an audio asset with its duration, so that the lip sync node needs no cutting and the clip it makes starts exactly where the slice starts. The singer's clip is never slowed down in the cut (it would lose the lips); a story clip may be slowed to 0.8.
- **The cut.** The boundaries are rounded to frames once (`round(time × fps)`) and every scene gets the difference of two boundaries, so nothing drifts against the song over 4 minutes. Crossfade and flash keep the boundary on the beat (the next scene starts at its boundary and fades in over the first part of its own time). One decoder thread per input. Up to `BATCH_SCENES` (3) scenes one ffmpeg run makes the film; more are cut in batches (next point).
- **Batches (memory).** Every scene is a filter chain with a decoder of its own, so one process grows with its scenes: 50 invented clips of 5 s (250 s) took 1.44 GB at 720p and 1.81 GB at 1080p in one process (exact peak of the ffmpeg process, `/usr/bin/time -l`, the encoder on three threads as x264 takes on 2 CPUs; 2.32 GB at 1080p with the encoder on all cores of the 10-core Mac). The server has about 2.5 GB free and the engine may run two cuts at once. A film of more than three scenes is therefore cut in batches (`buildEditPlan`, run by `lib/music-video-render.js`) so that no ffmpeg process opens more than `BATCH_SCENES` (3) clips: three scenes, or under a crossfade two scenes and the clip before them. One process per batch, one after the other, writes its frames raw (`yuv420p`, no times) to its standard output, the app hands them to ONE encoder process, which fades out, lays the song underneath and encodes the film once with the settings of the single run. Peak of the encoder plus the largest batch process for the same 50 clips: 1080p 0.61 GB (cut), 0.73 GB (flash), 0.72 GB (crossfade); 720p 0.35 GB (cut), 0.40 GB (crossfade). Run time on the 10-core Mac (median of three rounds, one after the other): a cut takes 41 s at 1080p and 20 s at 720p, as in one process (41 s and 19 s); a crossfade takes 52 s and 25 s against 48 s and 22 s, because the clip before every batch is decoded again; about 10 % more CPU in all, since the app copies the 19 GB of raw frames of the 1080p film through the pipe (8 to 9 s of CPU in the app). Why three: the largest batch process grows by 0.07 to 0.1 GB per scene at 1080p, while the run time hardly depends on the size (24 clips at 1080p: a cut takes 19.4 to 19.9 s with one to four scenes per batch, a crossfade 26.2 s with one, 23.4 s with four; the clip before a batch is decoded again, which is why smaller batches cost a little under a crossfade). Under a crossfade the first scene of a batch fades in from the end of the scene before it, which a second decoder of that clip delivers through the same chain (`trim=start_frame`, `xfade` at offset 0); every batch ends with `trim=end_frame` at exactly its frames, flash is per scene as before. Raw frames carry no times, so the renderer counts the bytes of every batch and stops the whole job when one does not deliver exactly its frames; an abort, a time-out or the end of any process kills all of them (no process is left and nothing is written but the output file in the scratch folder of the node, which `runOp` removes). The test compares the film of batches (of one and of three clips) with the film of one process frame by frame. Tried first and measured: intermediate segments joined with the concat demuxer (one decoder at a time, `-crf 12` between): about twice as long at 1080p (76 s in the trial), 200 MB on disk, a second lossy generation and a seam at every join; so the pipe.
- **The model.** One request for all scenes (`json: true`, system prompt in `planLib.systemPrompt()`), the answer is read scene by scene; a second request tells the model what was wrong; what is still missing gets plain prompts (`fallbackContent`), so the plan always completes. A failed second request keeps the first answer. The plan is paid by what the model charged (`cost.unit: 'usd'`, no estimate: the plan node's price is a few cents, the plan shows the last cost of the node).
- **Prices.** `audio.lyrics_timing` is priced by the hour of audio (`lyricsTimingUsd`, `ELEVENLABS_TIMING_USD_PER_HOUR`, default 0.22, the list price of Scribe v2, which the forced alignment costs as well; until 2026-10-03 0.40 with Scribe v1). It uses the length that the PR #10 estimate context gives (`context.inputs.audio.duration`): known for a song that a node made, unknown for an upload (an upload carries no duration); `history: false` keeps the plan from guessing from the last run. The prices of everything behind the plan (images, clips, lip sync) depend on the number of scenes, which the engine knows only once the plan node has run (the list lengths are cached): before that the template is `unknown` in the gallery, and the card of the chat shows "price unknown" and asks to accept the unknown steps. Once the plan has run, `fal.h3_lipsync` is priced from the slices of the song (`context.inputs.audio`, see the fal prices). The description of the template names the order of magnitude: a 2-minute song costs about 11 US dollars with the preset settings (about 26 to 30 scenes: 24 story clips of H3 Max turbo at 768P, 24 x 0.20 = 4.80; 28 images at about 0.13 (Nano Banana Pro), 3.75; 4 singer scenes of about 7 s at 768P, 0.08 USD a second, 2.40; the plan and the times a few cents), roughly 5 to 20 depending on the number of scenes, the image model and the video settings (the model max or 1080P for the clips: 15 to 20 and more).

### Captions, sound wave and the variant with moving images (WP35, part 1)

- **What it is.** Two local nodes, `video.captions` ("Burn in captions") and `video.soundwave` ("Sound wave"); the optional input `captions` and the settings `captions` / `captions_position` of `music_video.edit`; the template `music-video` ships karaoke captions; the new template `music-video-stills` moves the story scenes with the local zoom instead of paid clips. SPEC §5.7, §5.9, §5.10, §15.
- **A script, not a filter chain.** The captions are an ASS script (`lib/captions-ass.js`, pure) that libass draws (`ass=filename=`). Karaoke, outline, wrapping and positions are libass's work; `drawtext` has none of that, needs one filter per word and is missing from some builds as well. Rules the module keeps (each has a test, `scripts/test-captions-ass.js`, against an independent reader of the libass rules, `scripts/support/ass-reader.js`): `PlayResX/Y` are the size of the video, so sizes are in picture pixels; the size is a share of the height (automatic 6 %, times `min(1, width / height)`), the outline a share of the size; wrapping is a balanced division at a character limit that follows from width and size, set with explicit `\N` and `WrapStyle: 0`; the line shows from 0.4 s before its first word to 0.4 s after its last, and lines that follow each other closely share the time between them (middle of the gap), so two rows of text never stand over each other; karaoke is `\kf` in centiseconds with the unsung colour as SecondaryColour, a gap before a word is `{\k<gap>\kf<length>}` in ONE block (checked against libass 0.17.3: it adds them), a word fills until the start of the next one and the last until the end of its line; a line without word times gets evenly spread ones; `{`, `}`, `\` and line breaks of the text are escaped (ASS has no escape for the backslash, so it becomes the look-alike U+2216); `offset` moves everything. The fonts are a fixed list (DejaVu, Liberation, Noto; Sans and Serif; default DejaVu Sans), no path from a user ever reaches the filter.
- **Filter escaping.** The file name goes through two levels: option value (`\ ' :`) and graph (`\ ' [ ] , ; =`). `assFilter()` does both; the test reads a file with an awkward name back through `movie=filename=` with the same escaping, which works without libass.
- **libass is the one requirement.** `hasFilter('ass')` reads `ffmpeg -hide_banner -filters` once per binary (the flag column has two or three letters). `video.captions` has `available: libassAvailable` (listed as unavailable with the reason `ffmpeg has no libass (filter "ass")`, translated through `AVAILABILITY_REASONS` in `node-ui.js`), a `validate` that returns the error `CAPTIONS_NO_LIBASS` (the engine refuses to start on validate errors, but not on `available`, so this is what actually stops the run before anything is paid), and a last check in the builder. `music_video.edit` needs libass only if `captions` is not `off`, and then in the same way. A timing without lines (an instrumental) makes no script and no filter, so the video passes through and libass is not used. The picture also needs a font that fontconfig finds (`fonts-dejavu-core` for the default); nothing checks that, a missing font shows as boxes or a fallback face.
- **In the cut.** `editLib.captionScript()` makes the script for the size and the length of the film; the times of the song are moved by the start of the film (`bounds[0] / fps`). The script is written into the scratch dir of the run (`runOp` passes `{ scratch }` to an async `build`) and only the ENCODER draws it (`endOfGraph`, before the fade-out): once, also for a film cut in batches, whose batch processes make raw frames only.
- **The template ships it on.** `n4.timing` goes to `n12.captions`, `n12` has `captions: karaoke` and `captions_position: bottom`, and the form has the switch (`n12.captions`: off / karaoke / words / lines). The consequence: on a server whose ffmpeg has no libass the template does not run until the captions are off (`CAPTIONS_NO_LIBASS`, with a wording for the form: `nodes.issue.CAPTIONS_NO_LIBASS.app`). The template stays available in the gallery (its `requires` are provider keys; libass is a property of the node, and the captions can be switched off), and the Director can pass `n12.captions: off`.
- **Sound wave.** `showwaves` (modes `cline` default, `line`, `p2p`, `point`) or `showfreqs` (`bars`), as wide as the picture, in a share of its height, `overlay` with `eof_action=pass`. No libass. The sound is the video's (copied where it is AAC or MP3); a video without sound takes the audio input as its sound (`apad`, `-shortest`).
- **Variant with moving images.** `music-video-stills` is `music-video` with `image.to_video` (zoom `in`, `duration` 5 = `clip_seconds` of the plan, 25 fps = the fps of the cut) instead of `fal.h3_video`; the motion text of the plan has no reader; the singer scenes keep the lip sync. (In part 1 every story scene got the same slow zoom in; the cache per item and `ctx.itemIndex` of WP35, rest, replaced that: the template now uses `varied`, see below.) Cost for the description and for the tests: 28 images x 0.134 (Nano Banana Pro) = 3.75, four lip sync scenes of 7.5 s x 0.08 = 2.40, plan and times a few cents: about 6 USD for two minutes (3 to 10), against about 11; `scripts/test-nodes-templates.js` computes both parts from the price tables, so the text cannot drift from them.
- **How it was tested without libass.** The ffmpeg of the development machine has no libass (no `ass`, `subtitles`, `drawtext`), so: (1) the script is checked by the independent reader and by a scratch libass harness (libass 0.17.3 through ctypes, outside the repo) that rendered karaoke, words, lines, positions and wrapping and compared the pixels with the timings; (2) `scripts/support/fake-ffmpeg.js` has two stand-ins: `createFakeFfmpeg` answers `-filters` with a list it was given and writes down the arguments and the script (for availability, refusals and "no process was started"), `createAssStandIn` is the real ffmpeg that lists `ass` as present and replaces `ass=filename=…` in the graph by `null` after writing the script down (so whole runs, batches and the encoder, go through and the test sees the graph and the script); (3) the burn-in tests (`test-captions-ass.js`, `test-nodes-video-captions.js`, `test-music-video-captions.js`) check the real picture - text pixels at the right place, colours changing in time - when `hasFilter('ass')` and a font exist, and print `SKIP …` otherwise (still green). `scripts/test-nodes-music-video.js` runs the template through the engine with the stand-in. What no test here has seen: a real ffmpeg with libass drawing a real script (see the open points).
- **Tests.** New: `test-captions-ass.js`, `test-nodes-video-captions.js`, `test-nodes-video-soundwave.js` (lavfi clips: length, sound, size, wave pixels in the wave area), `test-music-video-captions.js`. Changed: the template, i18n, fal (node count), search (golden queries for the new words), run-service, templates and music video tests.
- **Open points.** (1) The burn-in tests have not run against a real libass in this repository's CI or on the development machine; run them once where `ffmpeg -filters` lists `ass` and a font is installed. (2) Before the server relies on the default captions: `ffmpeg -hide_banner -filters | grep " ass "` and a font (`fc-list | grep -i dejavu`) on the server; without them every music video run needs `captions: off`. (3) One zoom for all story scenes: settled in WP35, rest (`varied`, `alternate`, below). (4) Right-to-left and CJK text: settled in WP35, rest (columns, kinsoku, logical order, `words` instead of karaoke for RTL, font warning; below). (5) The auto size is an estimate of the text width from the character count (no font metrics), so a very wide font at a large size can wrap earlier than needed.

- **Parallax.** The shift of a pixel is its depth (0 to 1, from the red channel of the depth picture, blurred a little) times the progress of the clip `min(1, T/seconds)` times `PARALLAX_SHIFT` (5 % of the width) times the strength, at most 120 pixels (`displace` takes 8 bits around 128). ### Transparency through the ffmpeg nodes and video over video (WP33b)

- **What it is.** The cutout of `fal.video_segment` is a WebM (VP9) with an alpha channel, and until now every ffmpeg node behind it lost the transparency (the native VP9 decoder drops it) and every video op wrote MP4. Now: alpha is detected, read with the right decoder, kept by the ops that reshape one video, and a new node, `video.overlay_video`, lays a video over a video with that alpha. SPEC §5.7, §5.7a, §15; template `video-cutout-overlay`.
- **Detection and decoder.** `ffmpeg.streamHasAlpha` (tag `alpha_mode` = 1 on VP8 / VP9 in any case, or a pixel format `yuva*`, `rgba`, `bgra`, `argb`, `abgr`, `ya8`, `ya16*`, `gbrap*`) feeds `video.alpha` of `normaliseProbe` and so of `probeMedia` and `probeVideo`. `hasDecoder` / `hasEncoder` read `-decoders` / `-encoders` once per binary, keyed by the path of the binary (so a test can point `FFMPEG_PATH` at a wrapper that hides some codecs). `alphaDecoderOptions(video)` is `['-c:v', 'libvpx-vp9' | 'libvpx']` for VP9 / VP8 with alpha, `lost: true` when the decoder is missing.
- **Where it is applied.** `applyAlpha(spec, infos, …)` in `nodes-edit.js`, called by `runOp` right after the builder: it puts the decoder option before `-i` of every input with alpha and turns an output marked `alpha: true` into `container: 'webm'` (VP9 with alpha, Opus; the arguments are `ffmpeg.ALPHA_VIDEO_ARGS` and `ALPHA_AUDIO_ARGS`). It never touches a spec without an alpha input, which is how the arguments without alpha stay the same; the plans of `explainer.edit` and `music_video.edit` (`execute`) are `plain`: no decoder option, no WebM. `runOp` names the file by `ops.outputExt(output)` and passes `alpha` to `saveOutputFile` where the output probe says so.
- **Which ops.** Decided from the code, kept in `ops.ALPHA_KEEPING_OPS`: `video.trim`, `video.speed`, `video.resize`, `video.adjust`, `video.concat`. The brief of the work package also named reverse, loop, crop, flip, rotate and a fade of the opacity; those ops do not exist in the code, so they are not in the list. `video.merge_audio` takes a video and an audio and is not "one video reshaped" (it was left on MP4, like the overlay of an image, captions, the sound wave and the grid). `video.concat` is not an ffmpeg op of `nodes-edit.js` but the tool `concat_videos` (`lib/tools.js`, also used by the chat): it got an alpha strategy (`'alpha'` in `ffmpeg.concatVideos`, `alphaConcatArgs`) that is chosen when every clip has alpha and the encoders and decoders are there; the other strategies and their arguments are unchanged.
- **Marking.** The ledger entry gets `alpha: true` (`extra.alpha` of `completeAssetFile`), `valueFromLedgerEntry` puts it on the value (video and image), `poller.handleFalCompleted` probes a stored `.webm` result of fal (`webmHasAlpha`: one ffprobe, never throws). Uploads are not marked (a WebM with alpha that is uploaded shows no chequerboard; the ffmpeg nodes treat it right all the same), images are not marked either (open). `public/nodes/preview.js` adds `nv-alpha` to the video (card, large view, thumbnail, app view) and, in Safari and every iOS browser only, the line `nodes.preview.alphaSafari` below it (`isSafariBrowser`: iPhone, iPad, iPad as a Mac with touch points, else Safari without the Chrome, Firefox, Edge markers); `nodes.css` has the chequerboard with the tokens `--nv-checker-a/b` (dark tiles only: there is no light theme), and the thumbnail and app view are named in the rule because `.nv-thumb` and `.nv-appleaf-frame .nv-media` set a background of their own later in the file.
- **`video.overlay_video`.** `ops.buildOverlayVideo`: see the end of SPEC §5.7a. Decisions worth knowing: the layer is held at its last frame (`eof_action=repeat`) and `enable='lt(t,end of its run)'` takes it away, because `eof_action=pass` dropped the last frame of a layer a frame early (found with a test at 1.9 s of a layer that runs until 2.0 s); the result is always cut by `-t`, which also ends a looped layer; `loop_layer` adds `shortest=1` so the looped input does not keep ffmpeg waiting; `length: layer` with a loop and no `end` is the length of the background (a loop has no end). A chroma key runs on `rgba` and works on a layer without alpha; with a layer that has alpha and a key the key's alpha replaces it (not tested, not a case the template needs).
- **The template.** `video-cutout-overlay` (SPEC §15): `requires` `fal` and `ffmpeg` (the segmentation needs the key and ffmpeg; the overlay is an `edit-video` node). The gallery shows an estimate (0.095 USD, the upper limit of `fal.video_segment` for `max_seconds` 10 at 30 frames per second), not a price.
- **Tests.** `scripts/test-nodes-video-alpha.js` (detection, decoder, byte equality without alpha against `scripts/support/video-op-args-before-wp33b.json`, the ops of the list on real clips, the ops outside it, wrappers for an ffmpeg without decoder / encoder / Opus, `concat_videos`, `poller.webmHasAlpha`, the preview with a small DOM, `scripts/support/fake-dom.js`) and `scripts/test-nodes-video-overlay.js` (graph, and real runs: mixed colour at the right place for every parameter, lengths, sound by windows of `volumedetect`, the key). Both print `SKIP …` and stay green when the ffmpeg has no `libvpx-vp9` / `libopus`.
- **After the review.** (1) `test-nodes-video-alpha.js` checks libvpx-vp9 and libopus before it makes any VP9 fixture; without them it prints SKIP and the rest still runs, and the test runs itself once more with an ffmpeg that hides them (a wrapper script). (2) The chequerboard rule names `.nv-thumb.nv-alpha` and `.nv-appleaf-frame .nv-media.nv-alpha` (the later rules of the thumbnail and the app view had the same weight and won); the app view shows the Safari hint; the hint shows in every iOS browser. The light tiles are gone (no light theme). (3) `video.overlay_video` with `audio: mix` uses `amix=...:normalize=0` plus `alimiter` so the background keeps its level; `video.merge_audio` is unchanged (its arguments are part of the byte equality). (4) The golden file `scripts/support/video-op-args-before-wp33b.json` has a key `more`: captions, sound wave, grid, image to video and the concat of the tool, written by the code of main from `scripts/support/video-op-cases.js`, compared on the branch with probes from `normaliseMediaProbe`. Known and left as it is: a background of an odd size (129x129) fails in libx264 as `video.overlay_image` does on main; a `start` beyond the end of the background runs without a hint and the layer is never seen.
- **Changes in existing tests (deliberate).** `test-nodes-templates.js`: the list of expected templates gets `video-cutout-overlay`; the template is one of those that need the fal.ai key (the exclusion list of the "no key" assertion); its cost is an `estimate` (0.095 USD, the upper limit of the segmentation) where the other shipped templates have none; a block of assertions for its shape, `requires` and the price and Safari notes in its description. `test-nodes-fal.js`: the number of registered node types, 94 to 95. No assertion was loosened.
- **Open points.** (1) The live test: a real segmentation (paid, about 0.075 USD for 10 s) of a short clip, then `video-cutout-overlay` over a second video: does the WebM that fal sends still carry `alpha_mode` and a duration in the container (both did in the mini test of 2026-10-03, which the node was built from: VP9, `alpha_mode=1`, `format.duration` 2.0 s for a 2-s clip; without a duration `video.overlay_video` stops unless `loop_layer` is on), does the chequerboard show in Chrome and Firefox, the note in Safari. (2) Images have no alpha mark: a PNG with transparency (for example from `image.text_render` or `fal.remove_background`) shows no chequerboard; it needs a probe when the asset is stored. (3) An uploaded WebM with alpha has no mark either. (4) The time of VP9 with alpha: on a server with 2 vCPUs (ffmpeg 6.1.1, measured 2026-10-04 with `-deadline good -cpu-used 4 -row-mt 1`) a cutout-like clip (the object on a transparent ground, a third of the height) takes about 34 s per 10 s of 1080p30 and 18 s per 10 s of 720p30, so the 60 s that `fal.video_segment` allows at most stay well under `ffmpeg.PROCESS_TIMEOUT_MS` (10 minutes); a clip with detail and noise over the whole frame took 145 s per 10 s of 1080p30, so such a clip longer than about 40 s can reach the limit in an op of `ALPHA_KEEPING_OPS`. `-deadline realtime -cpu-used 8` was about 3 times faster with files about 1.8 times larger; it is not used. `video.overlay_video` writes H.264 like the other ops; reading the layer with `libvpx-vp9` adds little to that.

### Speech models of ElevenLabs

- **Choice.** `audio.tts` has `model_id` as a `select` with the options source `elevenlabs-tts-models` and `noDefaultEntry` (the node names its model itself), default `eleven_v4` (`DEFAULT_ELEVENLABS_MODEL_ID` in `lib/tools.js`, also the default of the chat tool `generate_speech` and of the two starter templates that speak). It never throws: with no key, or when the call fails (a key without the right to read models, a timeout, an unreadable or empty answer) the built-in `TTS_MODELS_FALLBACK` comes back (Eleven v4, v4 Turbo, v3, v3 Conversational, Multilingual v2, Flash v2.5, Flash v2, Turbo v2.5, Turbo v2); after a failure the call is tried again after 5 minutes, not with every request. The route answers for everybody (a model is no private data) and needs no key. The node-view assistant lists the models in its help (`DETAIL_SOURCES`) and checks a proposed model against the list.
- **Refused model.** `tts()` hands the model to the error classification: the error list of ElevenLabs names `model_not_found` (404), `unsupported_model` (400) and `model_access_denied` (403); they, and a 422 that points at `model_id`, become `ELEVENLABS_MODEL_REJECTED` with `data.model`. The node shows `nodes.issue.ELEVENLABS_MODEL_REJECTED` in the interface language; the chat gets the German message.
- **Text length.** The limit of 2500 characters (`TTS_MAX_CHARS`, `SPEECH_MAX_CHARS`) stays, one limit for every model: the docs of ElevenLabs (read 2026-10-03) list 5000 characters per request for v3, 10000 for v4 and Multilingual v2, 30000 for Flash v2 and 40000 for Flash v2.5; Turbo v2.5 and v2 are documented as equivalent to Flash, and for v4 Turbo and v3 Conversational the docs give no figure. A text that a model refuses as too long comes back as `text_too_long` with the plain message of ElevenLabs.
- **Price.** `speechEstimateUsd(text, modelId)`: the price page (https://elevenlabs.io/pricing/api, read 2026-10-03, the same for every plan) lists 0.08 USD per 1000 characters for Eleven v4, v3 and Multilingual v2 and 0.04 for v4 Turbo, v3 Conversational and Flash / Turbo (v4 and v4 Turbo are 72% off until 12 October 2026; the offer is not counted). `ELEVENLABS_USD_PER_1K_CHARS` (default 0.08, the list price; until 2026-10-03 0.30) is the price of a full-price model; the half-price models count half of it (`SPEECH_HALF_PRICE_MODELS`), a model that is not named counts as full price. The estimate is reserved, booked and shown with the model of the call (`elevenlabs/<model>`).

- **Choice of model in the new LLM nodes.** `model` is a `select` with the options source `brain-models`, default empty. Empty means Opus 5.5 if `access.brainModelAllowed` allows it, else the default model of the person, and the log says "... is not available for your account: X is used instead". A model chosen by hand that is not allowed is refused by `llm.completeText` (`RoleRestrictedError`, before the budget check). Without an OpenRouter key (only the ChatGPT subscription is connected) a blank model is not Opus either: `chooseModel` takes the default of the app (or of the person's list) and the log says "OPENROUTER_API_KEY is not set, so ... cannot be used: X is used instead"; `explainer.plan` then has no price estimate.
- **PDF to the model, hybrid.** The planner sends the text with page marks and, for a model that reads files, the PDF itself as a file part (`{ type:'file', file:{ filename, file_data:'data:application/pdf;base64,...' } }`, plugin `file-parser` with `pdf.engine:'native'`). At most 22 MB of PDF in all (the files go as base64, a third larger, next to the text with the page marks: 22 MB are about 29 MB of the 32 MB a provider takes per request) and 300 pages per file; what does not fit is named in the log and left out as a file (the text still goes). The verify pass uses the text only. A model without the `file` input modality, an unknown model, a failed model list (`discovery.brainSupportsFiles` answers false; unlike images, where unknown means yes) and every `chatgpt/*` model get the text only, with a log line.
- **Documents.** Poppler (`pdftotext -enc UTF-8` in reading order, no `-layout`; `pdftoppm`; `pdfinfo`) per page, in a child process under `ctx.withLocalSlot`. TXT and MD have no pages: sections of about 6000 characters act as pages (`pages_are_sections`). `max_pages` is a budget for all documents together; a document after the budget is listed in the info but not read. A PDF with less than 200 characters per page is flagged `scanned` (a model that reads files still sees it). A password-protected PDF stops the run with `DOCUMENT_ENCRYPTED` and a text that says what to do. `available()` is the requirement `poppler` of the templates (`REQUIREMENT_CHECKS.poppler`); `POPPLER_BIN_DIR` overrides the search folder (used by the tests to simulate a missing Poppler).
- **Upload.** `assets.saveUploadFile` checks a document by content (50 MB, `%PDF-`, UTF-8) and stores `bytes` and `pages` in the ledger; the upload route got the MIME map for pdf/txt/md and a 50 MB limit for documents only. The MCP tool `upload_asset` takes the same files through the same function, so a `.pdf` upload that was refused before is now accepted (`test-mcp-tools.js` uses `.docx` as the refused example). The MCP upload limits a document to 50 MB before it arrives (`uploads.limitFor`, used by the base64 path, the one-time link and the `max_bytes` of its answer), the description of `upload_asset` and its "Allowed" list name pdf, txt and md, and a `.pdf` that is none is refused with the reason of `checkDocumentFile` ("The file is not a PDF ..."), not with the text for images. Error messages of the tools do not carry paths of the server: the Poppler messages name the file, not the folder.
- **Research.** The plugin `{ id:'web', max_results, include_domains, exclude_domains }` of OpenRouter; the sources are the `url_citation` annotations. `llm.js` got `citationsOf` and `citationSpansOf` (`[{ url, end }]`) next to the text. `processResearch` turns Markdown links into `[n]`; where the model wrote none, the `end_index` of the annotation decides where `[n]` goes; sources the text did not use stand in one line "Further evidence". The system text says that numbers need a source. The node has no price estimate of its own (it depends on the search; the search costs about 0.7 cent each plus tokens): the templates name the order of magnitude, and `cost.history:false` keeps the engine from guessing from an earlier run.
- **Branding.** `input.branding` reads `lib/brandings.js`; the short profile has the guidelines cut at 8000 characters, the logo is the first raster file. A restricted person (participant, guest) gets `RoleRestrictedError('brandings')`, the option source `brandings` is empty for them. Without a branding the neutral profile `NEUTRAL_BRAND` is used and the output `logo` is empty (`emptyOutputs`).
- **The planner and what the app does instead of the model.** The model writes scenes; the app counts. `buildScript` computes the seconds from the words (135 a minute in German, 150 in English and Spanish; the sources card counts 3 s), splits a scene longer than 15 s, cuts the title to 6 words, the bullets to 3 of 7 words, the screen to 25 words, drops bullets that repeat the narration, replaces an anchor that is not in the narration by the first fitting word, drops invalid references and figures, synthesizes the sources card, and replaces the German eszett by "ss". Error-level problems (no scenes, empty narration, a scene too long, the length more than 35 % off, too few or too many scenes, a quote too long) cause exactly one repair request to the model; warn-level problems are repaired in code and written to `warnings`. A figure or a flow, a number and a quote are always `motion`.
- **Visual modes.** `motion`: everything is code. `mix` (default): numbers, quotes, figures and flows are motion; stills for at most `max_still_share` (0.35, slider up to 0.5); at most 2 clips and only with fal.ai. `ai_video`: every scene is a clip. A mode the account cannot do (no image model, no fal.ai key) is lowered; every lowering is a line in `downgrades` ({ scene, from, to, reason }) and in the log.
- **Verify pass.** One more request compares every narration, bullet and number with the material and a quote with the text; the answer can only shorten or remove. `verified` is true only when the answer covers every scene except the sources card. A partial answer (for example one cut off at `max_tokens`) leaves `verified:false`, names the skipped scenes in `unverified_scenes` and the problems are always logged ("The check pass is incomplete: Scene s6 was not checked."); the statements it did check are applied. An answer that would leave fewer than 3 scenes (a checker that empties every scene) is not applied: the script stays as planned, `verified:false`, the log says "The check pass was not applied" (both requests are paid). An answer that is not readable, or a failed request, leaves the script as it was and `verified:false`. A verified script carries `verified_hash`, a fingerprint of all narration and text on screen. The price of the check is in the estimate.

An invalid script stops with `EXPLAINER_SCRIPT_INVALID` and the list of issues. `verified` is kept only if the text still matches `verified_hash`; a script edited after the check (or a `verified: true` without the fingerprint) comes out `verified:false` and the log says "edited after the check against the sources".

(5) The lists: `narration` and `briefs` have one entry per scene (the sources card has an empty narration, a silent card for the voice step), `image_prompts` and `clip_prompts` only their scenes; `shots.scenes[i]` has the places (`narration`, `brief`, `image`, `clip`) and `spoken`. (6) The planner accepts at most 10 documents (`input.document`) and sends at most 22 MB of PDF to the model. (7) No retry without the file parts when a provider still refuses a request for its size. (7) Layout of the Design App for a long script text is plain.

### Explainer video production: voice, scenes, cut, workflows (WP37b)

- **What it is.** Nodes `explainer.voice`, `explainer.scene`, `explainer.edit`; templates `explainer-video`, `explainer-video-topic`, `explainer-video-presenter` (SPEC §5.12, §15). Pure modules: `lib/explainer-cues.js` (word times from characters, cues, scene length), `lib/explainer-scene.js` (prompts, checks, CSP, fallback, figure crop), `lib/explainer-edit.js` (timeline, sound graph, SRT). Adapter: `lib/nodes/nodes-explainer-video.js`. Groundwork in `lib/elevenlabs.js` (`ttsWithTimestamps`), `lib/tools.js` (`generate_speech_timed`, node-only, paid, shares `prepareSpeech` and `saveSpeech` with `generate_speech`), `lib/nodes/llm.js` (option `history`), `lib/nodes/nodes-documents.js` (`images`, `image_offset`, `page_images` in the info) and `lib/explainer-plan.js` (spoken words, `narration_context`, `info` for the titles of the documents, `clips` switch).
- **The measurement behind the design (2026-10-03, about 0.63 USD, a made-up 3-page report).** Render node: 23–34 s per scene of 6–10 s (3 to 5 times real time, one job at a time per node), so a film of 2 minutes with about 12 scenes needs 6–7 minutes of rendering; the node rounds the length up to whole frames (5.84 s gives 176 frames). Opus 5.5 reading a 3-page PDF: about 6400 input tokens (about 2100 a page), the planner needs `max_tokens` of at least 8000 (24000 are set). ElevenLabs `with-timestamps` on `eleven_v4` takes `previous_text` and `next_text`, gives the times of every character, and the audio is as long as the last time. Scenes: writing 0.03–0.07 USD (1200–2600 tokens, 12–21 s), looking at the frames about 0.03, a correction about 0.07; 12 scenes about 0.8–1.2 USD with the occasional correction. Round 1 (contract and building blocks only) gave 2 of 3 scenes with real layout errors (title and badge both absolute on one line; markings 94 % high over the labels); round 2 (layout in normal flow, attached pictures sent to the model, a marking only around its target, source line 30 px, a frame-exact duration) gave 3 of 3 without an error. The layout rules of round 2 are in `writerSystemPrompt`, they are required (the one about the source line is gone since the live test: the app writes the line, see "Fixes after the first live test" below).
- **Frame-exact scene length (decision, tested).** `sceneDuration(voice)` = voice + 0.4 s rounded up to whole frames at 30 fps (`frameExact`: 4.4 stays 4.4, not 133 frames). The HTML says `data-duration` = `durationAttr` = (frames − 0.02) / 30 rounded to 3 decimals ("5.866" for 176 frames), because the render node rounds up: written as "5.867" or "5.87" it would make 177 frames, while this value gives exactly N frames whether the node uses `ceil` or `floor + 1`. The check after the render accepts a difference of 2 frames (`FRAME_TOLERANCE`) and takes the video as it is. The test double of the render node uses `ceil`; the real node is to be measured in the live test (open point 1).
- **Cues.** The start of the anchor word minus 0.15 s, at least 0.2 s, never later than 0.3 s before the end of the scene; an anchor that is not found is found as a similar word or by its first strong word, else the elements are spread evenly (log). The writer is told the cues in seconds and must put every animation on the timeline at its cue (`tl.to(..., cueSeconds)`). A title that is the FIRST element comes at `MIN_CUE` whatever its anchor says (a live scene began about 2 s empty because its title was tied to the fourth word); the other elements keep their times, none of them can come before `MIN_CUE`, so the order holds, and the log notes it when the title thereby comes more than 0.3 s earlier. The rule is for narrated scenes; the silent sources card keeps its own steps.
- **Checks of the HTML and the CSP.** `checkCode` runs BEFORE `withCsp` (the policy itself names the jsdelivr host, which `checkCode` would refuse as an address). Forbidden are `fetch(`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `import(`, `sendBeacon`, `<iframe>`, `<object>`, `<embed>`, `<base>`, a refresh `<meta>`, `document.cookie`, `localStorage`, `sessionStorage`, `indexedDB`, `eval(`, `new Function`, `importScripts(`, workers, `window.open(`, `@import`, and any `http(s)://` address except the GSAP script, **including `xmlns`** (inline SVG needs none; the decision follows the order: no address at all). Fonts: at most 2 files of 400 KB each, the whole HTML under 2 MB (`embedFontsWithin`: where the document with the fonts would reach 2 MB, the fonts are left out with a log line and the system font stands in; the scene does not fail). `esc()` removes `http(s)://` from texts of the script so that a title with an address does not make the scene invalid.
- **Review fixes of the check (navigation, CSP place, GSAP path).** A first version let the code leave the page by *navigation*, which no policy of Chrome holds back (a CSP has no `navigate-to`): `location`, `top`/`parent`/`opener`/`frames`, a form, a link, `.click()`/`.submit()`, `open(`, `https:` without `//` or with backslashes (the URL parser makes `https://host` of both), a string that starts with `//` or `\\\\`, `srcset`, `.src`/`.href` set by script, `setAttribute` with any name but plain SVG geometry, classes and `data-*`, `createElement` of anything but a box, text or picture tag, `innerHTML`/`insertAdjacentHTML`/`document.write` (markup is written static), names written as strings (`window['fet'+'ch']`, `obj['a'+'b']`), `Function(`, `.constructor`, `globalThis`, `Reflect`, a static `import`, and every `<link>`. Rules about words (`location`, `fetch`, `top.`) look at the code only (`codeOf`: the document without the visible text between tags, comments and the rules of a `<style>`), so a title that says "Location" is fine. The GSAP address is exact (`isGsapAddress`: the package at `/npm/gsap@3.14.2/dist/`, no `..`, `%`, `&`, `#`, `?` or backslash), also in the address scan. The CSP now has `form-action 'none'; base-uri 'none'` and `script-src` only for `https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/` (a path with a trailing slash matches by prefix) instead of the whole host. `withCsp` takes comments out and puts the policy into the first `<head>` only when nothing but the doctype and `<html>` comes before it; otherwise (`<header>` instead of a head, a script before `<head>`) a fresh `<head>` with the policy is made right after `<html>`, so the policy is always before every script. The check stays a net with holes in principle (code can be written in endless ways): the CSP covers requests, the rules cover navigation, and the render node itself should block requests in the renderer (**open: request interception in the render node, a later work package**). The brief stands between `<brief>` and `</brief>` in the writer's and the checker's request (a `<` in it is written `&lt;`), so that text of a PDF cannot play a section of the request.
- **Vision check.** Two frames: at `min(50 %, last cue)` and at duration − 0.15 s, with the cues in the prompt (a frame before the cue of an element would report "number not visible yet"). The answer is `{ ok, blockers[], minor[] }`; only blockers lead to a new try, `minor` is logged. An unreadable answer is accepted with a log line (a scene is not thrown away because the checker failed). The retry continues the conversation through `history`: the HTML so far as the assistant, the problem and "give back the whole corrected HTML" as the user.
- **Fallback.** `fallbackHtml` is deterministic code (no model): title, at most 3 bullets or numbers (no source line of its own: the app puts one in as in every scene; the text column ends at 78 % of the height, above the free band), the colours and fonts of the brand, the still as a background where the scene has one. Its HTML passes `checkCode` in both formats (tested), and texts with addresses or markup are cleaned or escaped. With `fallback` off the scene stops with `EXPLAINER_SCENE_FAILED` and the problems of the last try.
- **Matching by id, not by position.** The brief starts with `Scene sN ...`; the entry with that id in `shots.scenes` gives the still index and the figure. The page images of `doc.read` are one list over all documents; `pageImageIndex` uses `images`/`image_offset` of the info (an older info without them counts from `pages_read`). A figure is cut with a margin of 2 % (`figureCropFilter`, `ffmpeg -vf crop`) from the 150 dpi page image; a missing still or page leaves the scene without it (log), never a wrong one.
- **Clip scenes.** `explainer.scene` does not draw a scene planned as `clip` (no model call, no render): a plain stand-in of the background colour of the exact length; `explainer.edit` replaces it with the next entry of `clips` (the lists meet by order of the clip scenes, in `shots.scenes[].clip`). The three workflows of the order have `clips: false` in the planner, so the chain is tested with the nodes but not shipped.
- **The soundtrack of the cut.** The cut mixes ONE soundtrack WAV first (voices on exact frame offsets at 48 kHz with `atrim`/`apad`/`concat`, music looped at the level quiet 0.12 / medium 0.25 / loud 0.45, ducking by `asplit` + `sidechaincompress`, then `amix`, `volume=2`, `alimiter`) and hands it to `music-video-edit.buildEditPlan` as the "song", so the encoder, the batches and the captions are the code of the music video. The offsets and the picture starts come from the same frame arithmetic (`planTimeline`), so the voice cannot drift against the picture (tested on 12 scenes, batched, by finding the onset of every voice tone with a Goertzel filter). A **mono voice or music** is widened with `pan=stereo|c0=c0|c1=c0`: the default up-mix of ffmpeg lowers a mono signal by 3 dB (found in the first test run). A crossfade of 8 frames (7.5 rounded) makes the film shorter by the overlap; the voice of the next scene starts when its picture is fully in. A hard cut next to the intro or the outro is a 1-frame fade, so **the intro loses its last frame of sound** (deliberate: the 1-frame fade is what keeps the joint clean). A fade is limited by both neighbouring scenes (`frames[index − 1] − 1`), otherwise a very short scene got a negative length. The soundtrack is levelled before it goes into the cut (see "Fixes after the first live test" below).
- **Length of the film.** The log names the real length and says "x % longer/shorter than planned" above 15 % (`lengthNote`); a crossfade and the 0.4 s pause explain a few percent.

### Assistant (WP25, server part)

- **Endpoint.** `POST /api/workflows/:id/assistant` (`lib/nodes/routes.js`, logic in `lib/nodes/assistant.js`). Permission as for editing the workflow (`guard`, 404 for a stranger). - **What the model gets.** One call, no tool loop: a system prompt in code (not the prompt file of the Director), the catalogue of all node types the person can use (id, label, cost kind, purpose, ports; participants and guests never see Higgsfield nodes), the full help of the best matching types (the palette search of `public/nodes/graph.js` over the question, the selected nodes and the open ends of the canvas; at most 8, the lists of `image-models`, `video-models` and the like as the inspector gets them), the starter templates for the person and the canvas as one line of JSON inside a fence with a random nonce (no media, no results, changed params only, free inputs per node). Question, history and canvas are marked as data. The model never names amounts; the app shows the estimate of the engine plan.
- **Strict check before anything is returned.** Types exist, are usable now and allowed for the role; params are cleaned (unknown ones dropped, numbers limited, texts clipped, media params dropped, a value from a list is checked against that list); ports exist and fit; new connections start at new or existing outputs and end at new inputs or free inputs of existing nodes; a connection into a taken single input (it would replace one) or a full multiple input (limit of the model included), an output a node never fills (`emptyOutputs`), duplicates and loops are refused; at most 20 new nodes. An invalid proposal is sent back once with the list of problems; if the second one fails (or the second call fails) only the answer comes back, with `insertRejected: true`. The client still applies it through `insertSubgraph` and checks the connections to existing nodes again.
- **Model and cost.** The model of a new chat of the person (`publicRuntimeConfig(viewer).defaultBrain`: the subscription for internal people when connected, the list of `restrictedBrainModels` or the regular models for participants), through `llm.completeText`: allowed models, budget check, booking of the real cost on the person and the backing session of the workflow, replacement through OpenRouter when the subscription fails (`usage.replaced`). Every question reserves a flat `COST_USD` (0.05) of the budget while the call runs (`estimateUsd` of `completeText`, released at the end), so questions at the same time cannot run past the budget of a participant; when the provider reports no cost, a participant is charged that amount (`unknownCostUsd`; `usage.usd` stays `null`). A participant with less than 5 cents left cannot ask.
- **Amounts in answers.** "Name no amounts" is an instruction in the prompt only; answers are not filtered. A model that names a price anyway is shown as it is. This is deliberate: a filter on `$`, `USD` or `CHF` next to a number would also hit harmless sentences (a duration, a resolution) and the cost the app shows comes from the engine plan right under the card.
- **Limit and logs.** 30 questions in 10 minutes per person (memory only; `RATE`, `createRateLimiter`). The log line `[assistant] {...}` holds the workflow id, role, language, model, number of calls, nodes and connections, result and duration; never a question, an answer, a title or the history.

### Assistant (WP25, the panel)

- **Where.** A button "Assistant" in the top bar (`nv-assistant-btn`, only with a workflow open) opens `aside.nv-assistant` in the column of the inspector (`.nv-body.assistant-open` hides the inspector; the button for the inspector brings it back). Under 701 px it is a sheet at the bottom (`position: fixed`, 82 % of the height) under the dialogs and popovers; the toast then moves to the top so it does not sit on the input. Esc closes it and returns the focus to the button; the keys of the panel never reach the canvas shortcuts (`stopPropagation` on the panel), so Delete on a focused button deletes nothing.
- **Conversation.** One per workflow, in memory (`threads`), until the page reloads; nothing is stored. The draft stays per workflow. One question at a time. The request is `summarizeCanvas` (plain params only: no media object, no empty text, texts cut; the selection; the issues of the last plan as warnings), the last 6 turns (`requestHistory`: no errors, nothing pending) and the interface language. Answers are plain text (paragraphs), never HTML; links to nodes are buttons "Open help for «X»" that call `nodeHelp.openPopover` and exist only for types the registry of this person knows.
- **Inserting.** `buildSubgraph` turns the proposal into a sub graph: temporary ids, a layout (a column per step of the flow, 380 px, a row per node, 340 px; `insertSubgraph` puts the block beside the existing content) and `links`. ALL connections of the proposal are `links`, between new nodes as well, so each one is checked again against the graph as it is now (the server checked against the unsaved summary of the client). `graphLib.insertSubgraph` adds them one by one with `checkConnection`; a single input that is taken, a full multiple input (model limit included), a duplicate, a loop, a missing port or node is skipped and reported in `skippedLinks` (`input_taken` is new); nothing is ever replaced or removed. Links alone (no new node) are allowed. It is ONE `applyGraph`, so one step in the history; the new nodes are selected and brought into view; nothing is run. The card says what happened ("N nodes inserted", the names, the connections, how many go to existing nodes, how many could not be set).
- **Undo.** The card's "Undo" calls the normal `undo()`, but only while the history is still at the step of the insertion (`history.revision`, a counter that every commit, undo, redo, reset and clear moves on and that never goes back; the position in the stack is no marker, because a full stack keeps its index and a reopened workflow starts at 0 while the conversation and its cards stay); after any other edit, or after the workflow was opened again, it is disabled with a hint, because the undo of the top bar would take back something else. It does not come back to "possible" later.
- **Cost.** After the insertion the page saves (`flushSave`) and asks the plan (`POST …/runs/plan`, which reads the saved workflow). Only the inserted nodes count: a paid node with an estimate and a known number of executions is summed; every other paid node (no estimate, `invalid`, a list of unknown length, no entry) is "unknown" and named as such; no paid node: "cost nothing in this app"; a failing plan: "could not be worked out". Never 0 for unknown. The tooltip repeats the usual estimate hint. Connections alone show no cost line.
- **Notes.** `adjusted` of the server becomes one sentence each (`unknown_param`, `clamped`, `clipped`, `media_param`, `unverifiable`, `not_a_number`); `insertRejected` says nothing was inserted; `usage.replaced` says the subscription was not reachable and the answer came through OpenRouter (with the amount, or "unknown" when `usd` is `null`); for participants (`billing: 'usd'`) the cost of the question is shown (unknown stays unknown) and the line "Budget left" at the top follows `budget` of each answer (and of the 402 body); the account menu is refreshed (`OCAccess.refreshMe`). Fewer than 6 questions left of the 30: a note.
- **Errors.** The server sends finished sentences in the language of the interface; the panel shows them as they are (`failure`). Budget used up or too small and "too many questions" get a warning look and no "Ask again"; a lost connection, a provider failure and an unreadable answer offer "Ask again" (the same question, the failed try is not part of the history). An answer that arrives after another workflow was opened is kept in its conversation, with the note "Not inserted", and nothing is inserted.
- **Tests and checks.** `scripts/test-nodes-assistant-ui.js`, the graph test for `links` (`testInsertSubgraphLinks`). The visual check ran in an isolated copy with the model replaced by a double (subscription and OpenRouter), a headless Chrome and made-up data: the panel with an explanation and the help link, the card after the insertion with the cost and the toast, a participant with a team budget (answer with its cost, then the budget message), each in German at 1440 and 390 px and in English at 1440 px.

## 3. How to add a node type

A node type is one registry definition plus i18n rows. The palette, card, inspector, validation, plan and run UX pick it up from `GET /api/nodes/registry`.

1. **Choose the module.** Pure logic → `lib/nodes/nodes-basic.js`; provider-backed → `nodes-generate.js` (via `tools.executeTool(ctx.toolCtx, …)` or `llm.js`); local ffmpeg / resvg → `nodes-edit.js`. For a new family create `lib/nodes/nodes-<name>.js`, export `registerAll(registry)` and add `require('./nodes-<name>').registerAll(defaultRegistry);` at the bottom of `lib/nodes/registry.js`. Higgsfield models need no code: they appear dynamically.
2. **Write the definition.**
   - `type`: `<family>.<name>`, matching `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$` and unique. `category` is one of `input, llm, text, image, video, audio, edit-image, edit-video, edit-audio, higgsfield, fal, utility, output` (a new category also needs an entry in `CATEGORIES`, `nodes.category.<id>` and a `--nv-cat-<id>` colour plus `[data-cat]` rule in `nodes.css`).
   - `version`: bump it whenever the output for identical inputs changes; it is part of the cache key.
   - `inputs` / `outputs`: `{ id, type, required?, multiple?, param?, hidden?, max? }`; port ids match `^[a-z][a-z0-9_]{0,31}$`; types are `text | number | image | video | audio | any`, each optionally as `T[]`. `param` names an inline fallback param for text / number ports. A scalar port fed by a `T[]` runs the node once per item, so executors never need to loop.
   - `params`: `{ id, kind, default, min?, max?, step?, options? | optionsSource?, optional?, inline?, showIf? }`; kinds `text, textarea, code, number, integer, slider, boolean, select, color, asset, assets, tags`; `optionsSource` is `brain-models`, `elevenlabs-voices`, `elevenlabs-tts-models`, `higgsfield-image-models`, `higgsfield-video-models` or `higgsfield-voices` (more via `deps.optionSources` of `registerNodeRoutes`).
   - `paid: true` and `cost: { unit: 'usd' | 'credits', estimate? }` for anything that costs money (this triggers the confirmation and the plan totals); `available()` → `true` or a reason; `validate(params, ports)` for problems that should show before a run; `async: true` for provider jobs.
   - `execute(ctx, inputs, params)` → `{ variants: [{ <outputPortId>: Value }], cost?: { usd?, credits? } }`. Useful `ctx` members: `log(label)`, `signal`, `sessionId`, `toolCtx`, `waitForJob(job)` (returns asset ids), `saveOutputFile({ kind, ext, sourceFile, prompt, cost, duration })`, `withLocalSlot(fn)`, `itemIndex`. Call provider functions through their module object (`or.createImage(…)`, never destructured), otherwise tests cannot patch them. For an ffmpeg node add a pure builder to `ffmpeg-ops.js` and an `ffmpegNode({ … })` entry in `nodes-edit.js`.
3. **Add i18n rows** to `public/nodes/i18n-nodes.js`, format `[key, de, en, es]`, German with Swiss spelling:
   - `nodes.type.<type>.label` (always);
   - `nodes.type.<type>.keywords` (comma separated synonyms the palette searches, most important first; required for every type with a video or audio port, see `testSearchKeywords`);
   - `nodes.port.<id>` for every port id that no other node uses yet;
   - `nodes.param.<id>` for every new param id;
   - `nodes.option.<value>` for every select option that is not a number, ratio or resolution (`/^[0-9.:]+[a-z]*$/i` stays literal).
4. **Test it.** Add cases to the matching script (pure logic / registry → `test-nodes-types.js`, mocked executors → `test-nodes-generate.js`, ffmpeg builders and real ops → `test-nodes-ffmpeg.js`, engine behaviour → `test-nodes-engine.js`), then run `node scripts/test-nodes-i18n.js`, which fails on any missing key. Some tests pin a module's type list (`test-nodes-types.js` the basic types, `test-nodes-generate.js` the generative ones) and `test-nodes-i18n.js` and `test-nodes-graph.js` assert at least 71 types: update those lists.

Mini example, a pure text node. Add it to the `definitions` array of `lib/nodes/nodes-basic.js` (`textValue` is already imported there):

```js
{
  type: 'text.uppercase',
  version: 1,
  category: 'text',
  label: 'Uppercase',
  keywords: ['upper', 'case', 'capital'],
  inputs: [{ id: 'text', type: 'text', required: true, param: 'text' }],
  outputs: [{ id: 'text', type: 'text' }],
  params: [{ id: 'text', kind: 'textarea', default: '', inline: true }],
  execute: async (_ctx, inputs) => ({ variants: [{ text: textValue(inputs.text.value.toUpperCase()) }] })
}
```

Its only missing translation is the type label (port `text` and param `text` already exist):

```js
['nodes.type.text.uppercase.label', 'Grossbuchstaben', 'Uppercase', 'Mayúsculas'],
```

Extend the `expected` list in `testBasicNodes` of `scripts/test-nodes-types.js` with `'text.uppercase'` and add an assertion next to the other `exec(…)` checks there, e.g. `assert.equal((await exec('text.uppercase', { text: textValue('a') }, {})).variants[0].text.value, 'A')`. A list wired into the `text` port makes the node run once per item and return a list, with no extra code.

## 5. Decisions (as of 2026-09-29)

- **Workflows follow the chat rules of the user management** (README). Without `AUTH_WHOAMI_URL` they are open to everybody and nothing is filtered; with it, new workflows are private and can be shared, and workflows without an owner stay open. `createdBy` / `updatedBy`, run users and cost users come from `req.kubleUser` (`lokal` without an auth proxy). The node view shows owner, share badge and share dialog through `public/access-client.js`.
- **Higgsfield edit nodes are experimental and untested against the live API.** They need Higgsfield connected (and ffmpeg for the ones that probe a source). Without `PUBLIC_BASE_URL` the sources are uploaded with `media_upload` since phase 2c (§2.6). One live verification (job id, result format, upload flow) is still needed and costs credits.
- **Phase 2 starts with Higgsfield lip sync / voice change / motion transfer (decided 2026-09-29).** Built as the experimental nodes `hf.dubbing`, `hf.voice_change`, `hf.motion_control` and `hf.speech`, the `media_upload` path, an audio input for `video.higgsfield` and the template «Clip in drei Landessprachen» (§2.6). The Director `run_workflow` tool and the mask painter follow after the live verification.
- **No mask for OpenRouter images.** Inpainting stays approximate (template "Masked edit": `image.edit` → `image.mask_apply` → `image.composite`). Whether the endpoint accepts a mask or a transparent background is unverified.
- **Cost estimate = last actual cost** of the node type in the workflow; otherwise "unknown". No price table; Higgsfield shows a credit estimate from the catalogue.
- **ElevenLabs costs are not journaled**, as in the chat; the TTS node shows no cost.
- **Deleting a workflow deletes its backing session including all assets**, after an in-app confirmation. No archive; cost journal lines remain.
- **fal.ai nodes are experimental and untested against the live API (2026-09-29).** All nine carry the badge until one paid call per endpoint has confirmed §2.7. Costs shown are list-price estimates; the realtime `director` endpoint is not implemented.
- **Canvas: left-drag = rectangle selection.** Hand tool (`H`) and select tool (`V`); Space, middle mouse and trackpad scroll pan. No setting to swap the defaults.
